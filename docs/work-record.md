# Current work

Started October 3, 2026. The commissioned outcome is a correctness-validated Chandra OCR 2 endpoint on Waystone’s Windows Intel GPU, selectable or load-balanced with NorthStone’s ROCm endpoint. The public repository preserves Const-me/Whisper’s history. It is a public GitHub fork, with complete model inference supplied by PyTorch XPU and native DirectCompute operators developed alongside it. The native graph is not yet a serving backend.

Waystone’s physical Arc A770 is PCI `0c:00.0`, device `8086:56a0`, with 15.88 GiB dedicated memory. The installation uses managed Python 3.12.14, PyTorch 2.14.1+xpu, Transformers 5.18.0 and the pinned BF16 checkpoint. The [runtime guide](../runtime/waystone/README.md) records exact dependencies, device selection, download verification and the narrow allocator-warmup workaround. Source, model files, runtime inputs and recoverable source snapshots remain project-owned. No global PATH, driver, drive-trust or firewall policy was changed.

The full CPU FP32 reference reached the correct end-of-turn token and matched the ROCm page’s text, tables and equations; one normalized bounding-box coordinate differed by one unit. The deployed hybrid vision-SDPA/text-eager configuration passed all three frozen PNG fixtures. Its tiny-page output matched the CPU reference’s ordered content, with a maximum bounding-box coordinate difference of 0.816 pixels. Full-sequence teacher forcing alone would have admitted an unsafe text-SDPA implementation: cached decoding diverged and complete OCR hallucinated. Full text SDPA remains excluded from serving. The [numerical evidence](../verification/evidence/README.md) preserves the comparisons, failures and their exact scope.

Native BF16 decoding, normalization and recurrent kernels passed synthetic checks. The recurrent primitive also passed on the first trained linear layer’s 801-token input on the identified A770. These operators do not yet include the model’s complete projections, vision encoder, tokenizer or generation graph. The [native evidence](../ChandraNative/README.md) separates trained-input evidence from earlier synthetic adapter checks.

Five warm representative-page requests took a median 11.069 seconds on NorthStone and 85.164 seconds on Waystone, each producing 397 completion tokens with a proper stop. These measurements cover one synthetic development page, not a general document workload. Native and scanned two-page PDFs also passed the exact Chandra CLI, checking prose, columns, equations, numerical table associations, page order, metadata and absence of HTML output. A separate recording proxy tied all four actual requests on each backend to frozen page pixels and verified their stop reasons and token counts. See the [measured acceptance](../benchmarks/evidence/README.md) for timings and artifact commitments.

NorthStone’s enabled user services own the router and the Windows worker through SSH and a heartbeat-supervised Windows Job Object. The ordinary API chooses automatically; selector base URLs choose a specific backend. Concurrent requests, streaming cancellation with retained capacity, and overflow routing have passed actual endpoint checks. After an unplanned host reboot, all three installed gateway/worker services recovered automatically. A fresh deliberate worker crash then passed: the partial stream stayed incomplete, the service restarted once, and recovery OCR was correct. Both real idle cycles passed, unloading after 300.586 and 300.715 seconds with zero Torch allocated/reserved GPU bytes; OCR after reload was correct. Existing ROCm service configuration remains independent.

Native Windows model listings passed through a temporary SSH tunnel, which was removed and verified closed. Direct Waystone access to NorthStone port 8002 timed out while SSH connected; local LAN binding is established, direct LAN reachability is not. The [operations guide](operations.md) explains endpoint selection, service ownership, tunnel access, bounded queues, retry limitations and rollback.

The performance hill climb is recorded under the [experiment index](../experiments/xpu-hillclimb/README.md). An unprofiled warm request took 85.497 seconds; profiling identified approximately 2,740 GPU kernels per decoded token, with recurrent updates and normalization as promising targets. The explicit-mask attention candidate failed its initial gate and moved early probability distributions further from CPU FP32. Compiled recurrence passed local structural checks with tiny operator errors, but both tested variants failed the frozen full-trajectory policy: six positions with ordinary compilation and eleven with contraction disabled. Native fused normalization failed at 17 positions, including an unapproved digit decision. These candidates are set aside. Cached normalization gains preserve all 395 logit rows, 25,280 cache records and five complete OCR pages exactly. Its first two timing pairs completed correctly, but extra peak allocation leaves the frozen memory qualification unresolved; the remaining three pairs and promotion are held. An unchanged-operation graph probe reported recording/replay unsupported on the installed A770 runtime. No optimized speedup has been accepted.
