# Current work

Started October 3, 2026. The commissioned outcome is a correctness-validated Chandra OCR 2 endpoint on Windows Intel GPU, selectable or load-balanced with the existing ROCm endpoint. This record distinguishes implemented components from deployment acceptance.

The public repository and upstream history are established. The first implementation checkpoint is `4f5ab80`. Waystone's physical Arc A770 is PCI `0c:00.0`, device `8086:56a0`, with 15.88 GiB dedicated memory. Vulkan, Direct3D and Level Zero execution have been exercised. Existing Python 3.12.14, uv, Visual Studio 2022, MSVC and Windows SDK support a project-local native installation.

Work is divided into the benchmark and numerical gates under `benchmarks/`, the exact-model XPU reference under `runtime/waystone/`, native DirectCompute operator work under `ChandraNative/`, and the HTTP worker/router under `chandra_service/`. Builds and installations are project-local. GPU work on each machine has one coordinating owner to avoid overlapping model allocations.

PyTorch 2.14.1 XPU ran the pinned BF16 model and completed a small synthetic OCR smoke request. The complete CPU FP32 reference also reached the correct end-of-turn token and matched the ROCm page's text, table and equations; one normalized bounding-box coordinate differed by one unit. Native BF16, normalization and recurrent kernels passed synthetic checks, and the recurrent primitive also passed on the first trained layer's 801-token input. These native operators do not yet constitute a complete recurrent layer or model graph.

Full-sequence teacher forcing was insufficient to qualify fused XPU attention. A complete OCR request hallucinated, and a separate cached-versus-full comparison exposed a large SDPA discrepancy. The hybrid vision-SDPA/text-eager configuration subsequently passed all three synthetic pages, including the 3,617-token representative input, with complete content and stopping metadata. Its tiny-page output matches the CPU FP32 reference except for bounding boxes, with a maximum coordinate difference of 0.816 pixels. Direct-backend generation took 82.18–86.69 seconds across the three pages; this single pass is not a repeated performance baseline. Full text SDPA is excluded from serving. Raw failures and numerical comparisons are retained; model or runtime changes require fresh evidence.

Serving source has been copied to Waystone with per-file verification and recoverable snapshots of replaced files. The Windows ownership supervisor passed actual process-tree cleanup checks for socket EOF, heartbeat expiry and a local service-channel stop. NorthStone user services now own the Windows worker and router, with cold/passive initial health verified. Synthetic endpoint acceptance is running; research workload handoff remains pending.

NorthStone's five warm representative-page runs passed at a median 11.069 seconds (11.051–11.078 seconds), each with 397 completion tokens and a proper stop. Its native and scanned two-page CLI fixtures passed in 18.845 and 17.954 seconds. Those successful CLI results used stock retry settings; subsequent deterministic Windows checks explicitly disable Chandra's temperature-changing retries. The CLI does not retain finish reasons, so content/metadata acceptance remains distinct from complete raw endpoint evidence.

Remaining acceptance covers representative complete OCR, repeated-request state isolation, numerical and semantic comparison, cold and warm performance, cancellation/crash/unload behavior, exact Chandra CLI compatibility, and deployed routing. The CPU-only transport tests include real socket cancellation, crash and idle behavior with task-owned fake workers; those tests do not establish GPU lifecycle behavior.
