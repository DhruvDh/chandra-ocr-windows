## Q8 KV experiment

The completed [C4/C6 experiment](../benchmarks/evidence/sycl-q8-kv-2026-10-16.json) explicitly changes both K/V cache types from BF16 to Q8_0, with text weights, fused vision leaf, projector, b128, full 16,384-token contexts and 12,384-token output allowances retained. Q8_0 is block INT8, not FP8. In this pin, quantized KV also activates Hadamard rotations (`n_rot_k=256`, `n_rot_v=64` versus BF16's 0/0), and eligible short-query attention changes from converted-half TILE to quantized VEC, including Q8_1 query arithmetic. Eligible prefill dispatch can change too. These results concern the supported Q8 configuration as a whole, not isolated scalar storage rounding.

The C4 numerical diagnostic reused four frozen native-1 windows and the existing independent full-vocabulary CPU rows, with one host CPU matching its BF16 control. All ten returned decisions matched CPU argmax and the teacher; none were missing or excluded after divergent history. At the weakest coordinate decision, CPU/BF16/Q8 winning probabilities were 0.421146269/0.411628376/0.416757750 and margins 0.162157059/0.091749251/0.121187210. Top-20 overlap was 19 there and 20 elsewhere. Candidate tails remain censored, rounded values are not renormalized, and candidate windows start with full-prefix prefill while CPU carries continuous cached history. This is finite conditional decoder evidence, not C6 decoder qualification or whole-model equivalence. The independent whole-vision reference is separate evidence and is not a decoder oracle.

A separate stock attention check confirmed VEC dispatch for Q1, four sequences, head 256, GQA4 and occupied KV 4096, comparing all 16,384 outputs against its quantized CPU reference at the unchanged upstream NMSE limit 5e-4. Actual NMSE and tensors were not exported. Packed initialized sequence strides avoid the rejected fixture's uninitialized reservation gap; the successful check does not cover that production gap, exact causal history, trained activations, cache updates or rotations. CPU query quantization and F32 accumulation of dequantized V make this implementation-agreement evidence, not an unquantized FP32 oracle. No operator speed was measured.

Separate private cold gates completed all four C4 pages and six overlapping C6 requests covering the same four cases, all with complete transport, natural stop and passing source predicates. Against retained BF16 C4 warmups, three C4 content strings were exact; scanned-0 differed only in four boxes by at most one normalized coordinate unit, with both geometries passing. The cold-gate elapsed times are not sustained rates. The private sustained cohorts passed all 140 warmup/measured checks in total and closed cleanly, retaining deliberate idle-retirement exit codes without establishing exact ten-second idle timing. The later installed normal-service results are separate observations described above. The earlier no-POST launcher failure and admission refusal remain preserved; successful diagnostic logging did not establish the admission refusal's cause.

A full slot's K/V storage falls from 512 to 272 MiB, while its FP32 GDN state remains 50.25 MiB. Six fully reserved Q8 slots therefore need 1,933.5 MiB of persistent KV/GDN payload, 315.5 MiB less than four BF16 slots' 2,249 MiB.
