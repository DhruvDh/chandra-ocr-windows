## Learning and promotion

Bounded complete-page runs and provisional timings may proceed while numerical questions remain open. Historical DirectCompute import audits, proof readers and progression holds do not impose a new engine's experiment sequence. Retain exact inputs, outputs, numerical differences and failures, and use targeted comparisons to investigate this implementation. Promotion requires numerical evidence, complete content and layout assessment, natural completion, cancellation/drain, independent request state and concurrency correctness.

Measure sustained correct pages per second with a replenishing client, no POST retries or prompt/image reuse, fixed context per request, adequate measured CPU supply, and warmup recorded separately. Report both in-window completions and complete-cohort time including drain; repeat adjacent concurrency points around the apparent plateau. Compare vision, prefill and decode against measured bandwidth and compatible arithmetic roofs, distinguishing BF16 matrix work from FP32 vector work. Nominal hardware rates, model loading, one page and short bursts each have narrower scope than a qualified throughput ceiling.
