# CPU FP32 export weight custody

The three retained CPU teacher exports record the model revision string, `tokenizer.json` and `config.json` hashes, the modeling-source hash and an exporter-script hash whose bytes were never retained. They record no safetensors digest and no model-loading directory, so [the importer](directcompute-cpu-reference.md) can convert them only on an owner attestation of the weights. Nothing here changes that history or those hashes. `verification/export_logits.py --custody` is an opt-in checked route for fresh CPU FP32 teacher exports that records contemporary custody of the checkpoint, producer and library files around the explicit loads, so root has objective fresh evidence on which to base that attestation. It is implemented by [cpu_custody.py](../verification/cpu_custody.py), which uses only the Python standard library. Without `--custody` every exporter route, argument, load call, admission and metadata write is unchanged.

The first finished implementation was rejected in independent review before any real export. Its exporter recorded the disk bytes it hashed after Python had already compiled the code, it never re-checked its retained producer copies or `sources.txt`, and a library source replaced by a FIFO blocked its hashing past the deadline. This version binds the executing code to the retained bytes and runs the export from them, re-authenticates every retained evidence file before and after acceptance, and opens every file it hashes without blocking. The second finished implementation was also rejected before any real export, on two findings. Its exporter computed the metadata digest of `logits.f32` with the ordinary blocking `sha()`, so a payload replaced by a FIFO blocked past the custody deadline, in both the cached and the full-teacher branches. A loaded library file removed before the manifest was collected was silently left out of an accepted `sources.txt`. This version reads that digest as acceptance reads payloads, and refuses a loaded library file that has disappeared. The sections below describe the repaired route. The schemas are `v2` so that no record of the first rejected route can be mistaken for one of this route. They stay `v2` for this repair because the second candidate made no real export, and every record retains its exact producer bytes, which the validation plan compares with the reviewed commit.

## Trust root and scope

The trust root is the tracked [provenance/model.json](../provenance/model.json) (checked out with `eol=lf`), whose SHA-256 `5cb10cc7ecd5fa31055ec9f18da92fd8bb0bb0c75803c095f336428fa84e2ee4` the exporter pins as `INVENTORY_SHA256`. A different inventory is refused before any output exists. The inventory must name `datalab-to/chandra-ocr-2` at the exporter's pinned revision, list 1 to 256 members with safe relative POSIX names, nonnegative integer sizes and lowercase SHA-256 digests, and pin `config.json`. It must also name exactly one of `model.safetensors` and `model.safetensors.index.json`. Duplicate or case-folded duplicate names are refused, as are names that are also a directory of another member. So is any member that could change Transformers resolution outside the safetensors route: `.py`, `.bin`, `.pt`, `.pth`, `.ckpt`, `.h5`, `.msgpack`, `.gguf` and pickle files, adapter files, and non-safetensors indexes. A single-file inventory may hold no other `.safetensors` file. A sharded inventory must hold only top-level shards, and the pinned index's `weight_map` must name exactly the pinned shards (no unpinned, unreferenced, nested or `model.safetensors` shard). The pinned checkpoint is single-file: `model.safetensors`, 10,591,220,088 bytes, SHA-256 `0804568be9f099d6479fad9ed77a4da4611f3c1e7bc6e009af7dce45e8aa3847`. Index-and-shard support is exercised only by synthetic tests.

`--custody` covers CPU FP32 teacher-logit exports only: the default cached teacher-decode route, `--check-cache-equivalence`, `--full-teacher` and `--all-teacher`. It refuses `--device xpu`, `--precision bfloat16` and `--activation-fixture`, whose `activation.json` would be accepted before the post-load pass. It also refuses `--greedy-max-tokens`, whose free generation the importer does not consume and the synthetic tests do not exercise. It runs only where descriptor-relative opens and listings exist (POSIX), so `--model` and the `--output` parent must be absolute, normalized and resolved: none of their components may be a symlink, and the refusal names the resolved path to pass instead. `--output` and its sibling `<output>.custody` must not exist. The interpreter must be CPython, because the producer binding below is CPython code-object equality. `--custody-hash-seconds` (default 1800, at most 3600) is the monotonic deadline of each hashing pass. Without `--custody` it is an argument error (exit code 2, usage on standard error). A custody helper that is not a regular file of at most 4 MiB, is a symlink or does not compile is refused, as is an exporter file that is no longer a regular file. Every refusal at this stage prints one JSON line with `"phase": "custody_refused"` and `"output_created": false`, exits with code 2 and creates nothing.

## What is checked, and when

1. Before anything is loaded, the route reads `verification/cpu_custody.py` once, opened with `O_NOFOLLOW | O_NONBLOCK` as a regular file of at most 4 MiB, and compiles and executes exactly those bytes as the helper. The helper then reads `verification/export_logits.py` once the same way, within the deadline. The route creates `<output>.custody/` and writes exact copies of both: `producer/export_logits.py` and `producer/cpu_custody.py`.
2. Producer binding. Each module captures, at import, the code object Python compiled for it and is executing (`sys._getframe(0).f_code` at module level). The session compiles each retained copy from its retained bytes and requires the result to equal that code object under CPython code-object equality: bytecode, constants (including every nested function's code), names, line and column table and exception table, but not the file name. If the exporter on disk changed after Python compiled it, for example during the slow framework imports, or Python executed a stale bytecode cache, the run is refused before the output directory exists and before anything is loaded. A refused receipt is written, and the retained copy shows what disk held. When both are equal, the export itself runs in a fresh module executed from the retained exporter compilation. The code performing the export is therefore compiled from exactly the retained bytes, and changes to the imported module's globals cannot alter it. The bytes Python first compiled can differ from the retained bytes only in text that does not change the compiled code, such as a comment on an unchanged line. The binding is recorded as `producer_execution` (interpreter, optimization level, files and rule).
3. The pre-load pass opens the model root with `O_NOFOLLOW` and walks it by file descriptor, without following links. It refuses any symlink, FIFO, device or socket, any unexpected file or directory (such as `pytorch_model.bin`, an unpinned index, `adapter_config.json`, `.cache/` or a leftover `.partial` download), any missing member, and more than 4,096 entries. It opens each member component by component relative to the root descriptor with `O_NOFOLLOW | O_NONBLOCK`, and requires a regular file of exactly the pinned size. It streams the member through SHA-256 in 8 MiB blocks, never reading more than the pinned extent plus one byte, and checks the deadline on every block. The digest must equal the pin. Each member's identity (device, inode, mode, link count, size, `mtime_ns`, `ctime_ns`) must be unchanged from the walk through the end of its read, and every directory's identity must be unchanged across the pass. The index is parsed only from the bytes that were hashed, at most 16 MiB.
4. Both explicit loads are then declared before either runs, and `load()` refuses a call whose loader, path or keyword arguments differ from the declaration, or that is repeated. The model load is also refused unless `admission.json` exists. The declared calls are exactly the exporter's existing `AutoProcessor.from_pretrained(model_root, local_files_only=True)` and `Qwen3_5ForConditionalGeneration.from_pretrained(model_root, dtype=torch.float32, device_map="cpu", local_files_only=True, attn_implementation=…)`. The path must be the verified root and `local_files_only` must be true. Torch dtypes are recorded as `torch.float32`, and other value types are refused.
5. After the processor load, the exporter computes its existing metadata digests (`tokenizer.json`, `config.json`, image, prompt, response, modeling source and `script_sha256`). Under `--custody` it computes them with the helper's bounded reader rather than a blocking `open()`: a regular file (a link to one is followed), read without blocking within the deadline. Values are unchanged. The route requires the `tokenizer.json` and `config.json` digests to equal the verified pins, `script_sha256` to equal the retained exporter bytes, and `model_source_sha256` to equal the manifest's record of the model class's source. It hashes the source and extension files of every loaded module in `transformers`, `tokenizers`, `safetensors`, `huggingface_hub`, `accelerate`, `torch`, `torchvision`, `PIL` and `numpy`, plus the shared libraries in `torch/lib`, and retains them as `sources.txt`, one `sha256  size  package-relative path` line each. Each library file is opened with `O_NOFOLLOW | O_NONBLOCK` and must be a regular file whose identity is unchanged while it is read, within per-file and total bounds. Every absolute `__file__` of a loaded module names the file that module came from, and it is listed whatever is there now. If that file has disappeared, or is a directory, FIFO, socket, device or symlink, hashing refuses the export and names it, for example `Library source transformers/x.py cannot be opened without following links: No such file or directory`. It is never waited on or silently omitted. A module without a string `__file__` (built-in, frozen, namespace package or extension submodule) and a relative pseudo-path such as a torch namespace object's `_ops.py` name no file and are not listed. A `torch/lib` that is missing or not a directory is refused. Its shared libraries are listed as the directory holds them when sources are collected, so a library removed before then is not named. The pinned uv environment installs regular files (its default link mode on Linux is hardlink), so a symlinked library file indicates a different environment. The route also names the classes that configure, model, process and tokenize this export (model, config, AutoProcessor, processor, tokenizer, image processor and video processor if present) with their source files and digests.
6. Before `admission.json` is written, the original producer files are re-read and every retained evidence file is reopened, as in step 7, so that corrupted evidence refuses before the model load. `admission.json` is then written with `runtime.custody`, and only then does the model load run. The exporter's computation is unchanged.
7. After the forward, the exporter writes `logits.f32` (the cached route has also appended `logits.partial.f32` row by row) and computes the metadata's `logits.sha256`. Under `--custody` that digest is read as acceptance reads payloads, relative to the `--output` directory descriptor, whose device and inode must still be those of the directory `admission.json` was written into. The payload is opened without following a link or blocking, and must be a regular file whose identity is unchanged while it is read within the deadline. The value is the SHA-256 the route without `--custody` computes with `sha()`, and the payload bytes are unchanged. A FIFO, a symlink (even to identical bytes), a removed file or a directory at `logits.f32`, or a replaced `--output` directory, is refused there: exit code 2, a refused receipt and no `metadata.json`, rather than a wait or an unrefused error. Before `metadata.json` exists, the post-load pass repeats step 3 and requires every member and directory record to be identical to the pre-load record. A rewrite with identical bytes, a replacement by an identical copy (new inode), a touch, a chmod, an extra shard, a removal and restoration, or a new symlink is therefore refused, as is any content or size change. The pass also re-hashes every recorded library file and both original producer files, and requires the final runtime to equal admission's apart from `attention_config`, with an unchanged custody record, inputs and response hash. It opens the `--output` directory with `O_NOFOLLOW`, requires the same directory `admission.json` was written into, and re-hashes every accepted payload relative to it (`logits.f32`, and for the cached route `logits.partial.f32`, against the metadata's SHA-256). Library files first imported after admission are hashed and listed in the receipt; one whose file has disappeared by then is refused. Retained evidence is then authenticated separately from the originals. The evidence directory is opened with `O_NOFOLLOW` and must be the directory created by this run. `producer/export_logits.py`, `producer/cpu_custody.py`, `sources.txt` and `../<output>/admission.json` are each opened by descriptor without following links. Each must be a regular file with its identity unchanged since the session wrote it (device, inode, mode, link count, size, `mtime_ns`, `ctime_ns`, so still a single link), holding exactly its committed extent and SHA-256. A changed, truncated, grown, touched, hard-linked, replaced, symlinked, FIFO or missing evidence file is refused.
8. Acceptance writes `receipt.json` with status `accepted` and the SHA-256 of the exact `metadata.json` bytes, and fsyncs it. It then writes `metadata.json` through `.metadata.json.partial`, fsync and one rename, and re-reads it against that SHA-256. It reopens every retained evidence file once more, and re-reads `receipt.json` against the bytes written. `metadata.json` therefore never exists without an accepted receipt that names it and evidence that matched after it was written. If writing `metadata.json` or any final check fails, both names are removed and the receipt is rewritten as `refused`. A process killed between the two steps leaves an accepted receipt without its `metadata.json` (or a stray `.metadata.json.partial`, which the importer refuses), and the export must be treated as failed. A change made to the evidence after acceptance is detectable only by re-hashing it against the receipt, as the validation plan below does.

Any custody failure after `<output>.custody/` exists writes `receipt.json` with status `refused` and a one-line error of at most 4,096 characters. It prints a `custody_refused` JSON line with `metadata_written: false`, exits with code 2 and leaves no `metadata.json`. Any unaccepted payload that was already written, such as `logits.f32`, stays in place as unaccepted evidence. Any other exception (a loader or forward failure, an interrupt) also writes a refused receipt and then propagates as before. The model load and forward themselves have no new deadline; the existing memory gates still apply.

Every read the custody route performs opens a regular file without blocking, so a FIFO, socket or device is refused at once rather than waited on, and the deadline is checked before every open and every 8 MiB block. A read the kernel itself stalls, such as one on a hung network filesystem, cannot be interrupted between blocks. The loaders, Pillow and the exporter's existing prompt and response reads are not custody reads. Neither are the exporter's own payload writes, NumPy's `tofile` for `logits.f32` and the row append to `logits.partial.f32`, which are unchanged so that the payload bytes are unchanged. A FIFO planted in the export directory by another writer would block such a write, and a non-regular payload is in any case refused at its first digest. All of these are bounded only by the outer `timeout` of the validation plan. The `--greedy-max-tokens` and `--activation-fixture` payload digests still use the ordinary `sha()`, but `--custody` refuses both routes before any output exists. `metadata.json` and `receipt.json` are re-read after they are written with the same bounded reader, limited to the bytes written and to the helper's 3,600-second hard deadline rather than `--custody-hash-seconds`.

## Where the evidence lives

The importer refuses any export-directory entry the exporter never wrote, authenticates the whole `metadata.json` by SHA-256, and requires admission and final `runtime` to agree apart from `attention_config`. The custody record therefore lives in `runtime.custody`, identical in `admission.json` and `metadata.json`. Everything observed after admission lives in the sibling `<output>.custody/`, which the importer never reads. `runtime.custody` (estimated at about 8.5 KB as compact JSON for the pinned 17-member inventory: the earlier 7.9 KB record plus the producer binding) holds the following fields:

- `schema` `chandra.cpu-export-custody.v2`, `model`, `revision`, and `inventory` (file, SHA-256, bytes, member count and total member bytes);
- `model_root`, the explicit resolved directory, recorded verbatim;
- `checkpoint`: layout, each weights file's size and SHA-256, and the index summary if sharded;
- `before_load`: every directory's and member's role, size, SHA-256, device, inode, mode, link count, `mtime_ns` and `ctime_ns`, plus bytes hashed, elapsed seconds and deadline;
- `loads`: the declared processor and model calls (callable, path and keyword arguments), and `processor_load_completed_before_admission`;
- `producer` (SHA-256, bytes and copy path of both producer files), `producer_execution` (interpreter, optimization level, bound files and the binding rule), `sources` (file count, bytes and `sources.txt` SHA-256, plus the named computation classes), `evidence_directory` (`../<output name>.custody`), the acceptance rule and the evidence statement.

`<output>.custody/` holds `producer/export_logits.py`, `producer/cpu_custody.py`, `sources.txt` and `receipt.json` (`chandra.cpu-export-custody-receipt.v2`). The receipt records the status and error, export directory, model root, inventory, the `admission.json`, custody-record (canonical JSON) and `metadata.json` SHA-256s, and the re-verified payloads. It also records the producer binding and `retained_evidence`: the extent and SHA-256 of every retained file as re-verified immediately before acceptance, each equal to the corresponding declared producer, manifest and admission digest. The `custody_accepted` line prints the receipt's and the metadata's SHA-256. It also records the export entries present just before `metadata.json` was written, the before-load record, the declared and actual loads with timings, the complete after-load record and library re-check, what the loaded objects report (`name_or_path`, `config._name_or_path`, `dtype`, informational only and not gated), and limitations. Keep the export directory and its `.custody` sibling together. The model root, export path and inode numbers are machine facts that the importer repeats into every dump record and report, so choose paths without private information. Curated public evidence should cite hashes rather than paths.

An accepted export imports with the reviewed importer exactly as it stands. Pass `--producer-source <output>.custody/producer/export_logits.py`, which matches `script_sha256`. Because the importer still records weights only as an owner attestation, root may pass `--attest-model-sha256 0804568be9f099d6479fad9ed77a4da4611f3c1e7bc6e009af7dce45e8aa3847` with a basis naming the accepted receipt's SHA-256 and `metadata_sha256`, after confirming the checks in the validation plan below. The importer will still list `model_safetensors_sha256` among the missing producer commitments, because it does not read `runtime.custody`; the attestation is what binds them. The forecast of `--max-output-bytes` grows by roughly the custody record size for every dump record, plus the plan and report.

## What this evidence is and is not

The evidence covers the named files before and after the explicit loads, the code-object binding of the two producer files, and the arguments those loads received. It does not prove which bytes Transformers, safetensors or the operating system actually read. The producer binding covers the exporter and helper modules only: interpreter start-up hooks (`site`, `sitecustomize`, `.pth` files, which `python -I` limits) and library code are outside it, as is the interpreter itself. A change made and fully reverted between the two passes, timestamps included, cannot be observed this way. Directory and file `ctime` comparisons make such a reversal require changing the system clock, but the window is not closed. Library sources are hashed as files on disk: Python may execute cached bytecode, and the interpreter, standard library and system libraries outside `torch/lib` are named only by version. Arguments the producer does not pass take the defaults of the recorded Transformers sources. Network filesystems whose `ctime` or inode reporting is unstable will refuse rather than pass. Custody qualifies no logits, numerical agreement, cache equivalence or OCR result, and it does not turn a monolithic teacher row into a cached decode step. AMD remains the complete OCR reference.

## Root validation plan (not executed here)

Run this on the Linux CPU host only, with no GPU allocation. It needs at least 30 GiB available memory, as the existing gates require, and the model root as a plain directory written by `scripts/download_model.py`. The task-owned environment is `verification/cpu/.venv` from `uv sync --frozen --python 3.12`. Expect two complete reads of the 10.6 GB checkpoint, one before and one after the run, in addition to the existing load and forwards. Bound each command with `timeout` and stop on the first refusal: record it, keep `<output>.custody/` and never reuse an output path.

```bash
MODEL_ROOT=$(realpath "$MODEL_ROOT")   # The resolved directory; custody refuses symlinked components.
EXPORT="$PWD/results/cpu-fp32-custody-tiny-01"
# 1. Refusals that create nothing (seconds, no model load).
verification/cpu/.venv/bin/python -I verification/export_logits.py --custody --device xpu --model "$MODEL_ROOT" \
  --image benchmarks/inputs-v2/tiny.png --prompt benchmarks/prompt.txt --response "$RESPONSE" --output "$EXPORT-refusal"; echo "exit $?"   # expect 2
# 2. Cached teacher-decode export: prefill plus eight teacher steps, as cached 06.
timeout 5400 verification/cpu/.venv/bin/python -I verification/export_logits.py --custody --custody-hash-seconds 1800 \
  --model "$MODEL_ROOT" --image benchmarks/inputs-v2/tiny.png --prompt benchmarks/prompt.txt --response "$RESPONSE" --output "$EXPORT"
# 3. Independent checks before any attestation. The retained producer must be the committed, reviewed source.
sha256sum "$EXPORT/metadata.json" "$EXPORT.custody/receipt.json" "$EXPORT.custody/sources.txt" "$EXPORT.custody/producer/"*
git diff --quiet HEAD -- verification/export_logits.py verification/cpu_custody.py && git show HEAD:verification/export_logits.py | cmp - "$EXPORT.custody/producer/export_logits.py" \
  && git show HEAD:verification/cpu_custody.py | cmp - "$EXPORT.custody/producer/cpu_custody.py" && git rev-parse HEAD
python3 -I - "$EXPORT" <<'EOF'
import hashlib, json, pathlib, sys
e = pathlib.Path(sys.argv[1]); c = pathlib.Path(str(e) + ".custody")
r = json.loads((c / "receipt.json").read_text()); m = json.loads((e / "metadata.json").read_text()); a = json.loads((e / "admission.json").read_text())
sha = lambda p: hashlib.sha256(p.read_bytes()).hexdigest()
k = m["runtime"]["custody"]
assert r["schema"] == "chandra.cpu-export-custody-receipt.v2" and k["schema"] == "chandra.cpu-export-custody.v2"
assert r["status"] == "accepted" and r["metadata_sha256"] == sha(e / "metadata.json") and r["admission_sha256"] == sha(e / "admission.json")
assert a["runtime"]["custody"] == k and r["after_load"]["model_root"]["members"] == k["before_load"]["members"]
assert k["checkpoint"]["weights"] == [{"file": "model.safetensors", "size": 10591220088, "sha256": "0804568be9f099d6479fad9ed77a4da4611f3c1e7bc6e009af7dce45e8aa3847"}]
assert r["producer_execution"] == k["producer_execution"] and k["producer_execution"]["files"] == sorted(k["producer"])
evidence = r["retained_evidence"]  # Every declared evidence digest, joined to the bytes now present.
assert sorted(evidence) == sorted([f"../{e.name}/admission.json", "producer/cpu_custody.py", "producer/export_logits.py", "sources.txt"])
assert all(v == {"bytes": (c / n).stat().st_size, "sha256": sha(c / n)} for n, v in evidence.items())
assert all(evidence["producer/" + n.rsplit("/", 1)[1]]["sha256"] == v["sha256"] == r["producer"][n]["sha256"] for n, v in k["producer"].items())
assert evidence["sources.txt"]["sha256"] == k["sources"]["manifest_sha256"] and evidence[f"../{e.name}/admission.json"]["sha256"] == r["admission_sha256"]
assert m["runtime"]["script_sha256"] == sha(c / "producer/export_logits.py") and m["runtime"]["model_source_sha256"] == k["sources"]["classes"]["model"]["sha256"]
assert k["inventory"]["sha256"] == "5cb10cc7ecd5fa31055ec9f18da92fd8bb0bb0c75803c095f336428fa84e2ee4"
print(json.dumps({"receipt_sha256": sha(c / "receipt.json"), "metadata_sha256": r["metadata_sha256"], "loads": k["loads"], "producer_execution": k["producer_execution"]}, indent=1))
EOF
# 4. Import: dry run, then conversion with an attestation whose basis names the receipt.
python3 -I scripts/native/import_cpu_diagnostics.py --export-dir "$EXPORT" --metadata-sha256 "$METADATA_SHA256" \
  --input-manifest "$INPUT_MANIFEST" --input-sha256 "$INPUT_SHA256" --route cached-teacher-decode --rows 0,1,2,3,4,5,6,7,8 \
  --producer-source "$EXPORT.custody/producer/export_logits.py" \
  --attest-model-sha256 0804568be9f099d6479fad9ed77a4da4611f3c1e7bc6e009af7dce45e8aa3847 \
  --attestation-basis "fresh --custody receipt $RECEIPT_SHA256 accepted metadata $METADATA_SHA256; model.safetensors verified before load and after export" \
  --max-input-bytes 64000000 --max-rows 9 --max-output-bytes 16777216 --deadline-seconds 600 --output "$FRESH_IMPORT_DIRECTORY"
```

The exporter records its runtime and memory as before. Compare the fresh cached rows with the retained cached 06 import only as two CPU builds, never as a native result. An all-teacher (`--all-teacher`) custody export follows the same commands with the monolithic route, writes a 391,352,320-byte payload, hashes it for its metadata digest and re-hashes it once at acceptance. If any check in step 3 fails, do not attest; record the receipt and the failure.

`test_cpu_custody.py` builds model directories of a few bytes with fake loader callbacks. It accepts the tracked inventory as single-file and checks the exporter's pin against its bytes. It verifies a single-file and a sharded layout, and refuses unsafe, duplicate, ambiguous and loader-significant inventory names. It refuses wrong shard indexes, digest, size and config mismatches, and unexpected files and directories. It also refuses missing members, symlinked members and directories, FIFOs, symlinked or unnormalized roots and roots replaced by a symlink, and reused output or evidence paths. It checks that load arguments are declared, stable and recorded, and that every deviation is refused before the loader runs. It checks nine kinds of change during the load, as well as admission, payload, custody-record, runtime, input, original producer and library changes. Each is refused without `metadata.json` and with a refused receipt. It also covers a failed metadata write, a failing loader, and refusing to overwrite an accepted receipt. It covers deadline validation and expiry, block-bounded streaming that reads one byte past the pin, and growth or touches during a read. It checks source manifests and a real importer conversion, cached and monolithic, of metadata written by a session.

The producer-binding tests require the pre-load pass to follow a binding, and refuse a retained exporter or helper that compiles to different code, missing, extra or non-code entries, and uncompilable bytes, each with a refused receipt that keeps the retained bytes. They also check that the loaded helper binds to its own file and not to an edit, and that a script run as `__main__` by a child interpreter binds to its bytes but not to an edit made after it started. The retained-evidence tests corrupt each of `producer/export_logits.py`, `producer/cpu_custody.py` and `sources.txt` in eight ways while the originals stay untouched: other bytes of the same extent with the old `mtime`, growth, an identical new file, a symlink, a FIFO, removal, a hard link and a touch. They also replace the evidence or export directory with a copy or a symlink, and replace `admission.json` by a FIFO or identical copy. They cover corruption before admission (refused before the model load), corruption while `metadata.json` is written (metadata withdrawn, receipt refused), and the accepted receipt's `retained_evidence` joined to the actual bytes. The bounded-read tests replace a library source by a FIFO in-process and in a child given a 0.02-second deadline, and replace library sources and original producer files by FIFOs and symlinks within a session. They check source listing, the per-file and total bounds and a change while hashing, and the exporter's metadata digests (links followed; FIFOs, directories and missing files refused). They list every absolute module file, refuse a missing one and one replaced by a directory, both before the manifest (no `sources.txt` is retained) and for a module first imported after admission (no `metadata.json`), and refuse a missing `torch/lib`, while modules without a file and relative pseudo-paths are not listed. The payload-digest tests require the first payload digest to equal the ordinary digest of a regular payload, and refuse a FIFO, a symlink, a removed file, a directory, a replaced `--output` directory, a change during the read, an expired deadline and a call before admission or for another directory. If the directory is replaced after its check, the payload is still read from the admitted directory and acceptance refuses the replacement. Every FIFO case runs under a 10-second `SIGALRM` guard, or a 60-second child timeout, so a regression fails rather than hangs.

`test_export_custody.py` runs `export_logits.py`'s own `main()` with fake Torch, Transformers and Pillow modules and synthetic `/proc` memory readings, so the exporter's own memory gates run, including in the retained module. It covers accepted cached and all-teacher custody exports, including load order relative to admission and the evidence directory, recorded and actual load arguments, sources, producer copies, binding, retained-evidence digests, the printed receipt digest and real importer conversions. For that importer step only, the pinned modeling-source, tokenizer and config digests are replaced by the fixture's. It also covers a change during the model load, a failing forward, every pre-output refusal, and the unchanged route without `--custody`. Its producer-binding tests run checkouts of the exporter whose fixture inventory is pinned in their own `INVENTORY_SHA256`. They reproduce the review's control (compiled with eight threads, disk changed to three, then refused with no thread call, no load and no output, while the unedited copy is accepted with eight threads). They also refuse a stale bytecode cache, which the route without `--custody` still executes, and show that a change to the imported module's globals does not reach the custody export. In a child interpreter running `python verification/export_logits.py` as a real `__main__` script, the unchanged checkout is accepted and an edit made while Pillow imports is refused. Unreadable helper or exporter files are refused before output, and `tokenizer.json` replaced by a FIFO after the pre-load pass is refused finitely. For the cached, full-teacher and all-teacher routes, the payload tests show that a regular payload has the same bytes, `logits` metadata and SHA-256 with and without `--custody`, and that no custody digest goes through the blocking `sha()`. They replace `logits.f32`, right after it is written, by a FIFO, a link to a FIFO, a link to an identical copy and nothing. Each is refused at the first digest, with exit code 2, a refused receipt and no `metadata.json`, under a 1-second custody deadline and a 5-second `SIGALRM` guard; the fixture removes every FIFO before a failure propagates. A module loaded from its own file and executed during the processor load, whose file is then removed, is refused before `admission.json`, `sources.txt` or the model load. One imported during the model load and removed is refused before `metadata.json`. Modules without a file still accept. None of these tests imports a framework, loads a model or allocates more than about 100 MiB.
