# DirectCompute CPU reference import

The [CPU export-custody repair](directcompute-cpu-export-custody.md) is independently cleared at source scope: 72 supplied tests and 17 independent tests pass under pinned Python 3.12.14. It binds the retained exporter code, rechecks retained evidence, refuses blocking or substituted payload/source reads, and no longer omits a deleted loaded-module source. The [source record](../benchmarks/evidence/directcompute-cpu-custody-source-2026-10-06.json) preserves the original failures and honest limits. Historical weights attestation remains withheld; no fresh real-model reference or trained numerical acceptance follows from these fake tests.

[import_cpu_diagnostics.py](../scripts/native/import_cpu_diagnostics.py) converts selected complete full-vocabulary logits rows of a retained `verification/export_logits.py` CPU FP32 teacher export into the diagnostic v2 dump format that [compare_diagnostics.py](../scripts/native/compare_diagnostics.py) loads, so root can compare native trained rows with actual CPU rows. It uses only the Python standard library and never imports Torch, loads a model, uses a GPU or contacts a service. It computes no values: each selected 248,320-word row is copied word for word from the single stream whose SHA-256 the producer metadata names, declares no BF16 boundary (`bf16_rounding: none`), repairs no NaN and fits no tolerance. An import qualifies nothing; it only makes an honest reference available to the existing comparator.

## What a retained export records

The exporter's `metadata.json` records the model revision, `tokenizer.json` and `config.json` SHA-256, image and prompt SHA-256, processor profile, the five processed tensor hashes, prompt token IDs, teacher or target token IDs, runtime versions, the imported modeling-source and exporter-script SHA-256, per-call cache tensor shapes and hashes, and the logits payload shape and SHA-256. Its `context.positions` field lists absolute causal rows of the logits, not three-axis M-RoPE coordinates. It records no safetensors digest, no three-axis positions, no chat-template or preprocessor hashes and only a hash of the response bytes. The script bytes of the three retained exports are not in this repository: their `script_sha256` values match no committed revision of `verification/export_logits.py`, including line-ending variants.

## Routes and phases

`--route` is the owner's explicit statement of how the producer ran, and the importer checks it against producer-recorded structure rather than a directory name. `cached-teacher-decode` requires no `teacher_token_ids`, logits rows at the last prompt row followed by one row per target, full-attention key lengths `P, P+1, …, P+T` in successive cache snapshots and a manifest prompt of exactly `P` rows. Source row 0 becomes prefill logits at absolute row `P−1` producing generated index 0; source row `d+1` becomes decode step `d`, consuming target `d` at absolute row `P+d` with the same decode metadata the native recorder writes and producing generated index `d+1`. If present, `logits.partial.f32` must be byte-identical to `logits.f32`.

`monolithic-teacher-prefill` requires recorded `teacher_token_ids`, targets equal to the teacher token at every recorded row, exactly one cache snapshot whose key length is prompt plus teacher rows, and no `cache_equivalence`, `memory_positions` or `logits.partial.f32`. Every row of such a forward is prefill. The comparator accepts prefill logits only as the last row of the declared prompt, so a monolithic row is admissible only when its consumed prefix is exactly the manifest's prompt. Against the 801-row tiny input only absolute row 800 qualifies. Any later row is refused, because the v2 format would otherwise have to label it a cached decode step. The refusal names what root must obtain: an input manifest whose prompt is exactly that row's consumed rows (the processor prompt followed by the first `k` teacher tokens), together with a native prefill on it, or a cached teacher-decode CPU export reaching the matching step. The importer already accepts such an extended manifest. The first 801 rows of its integer tensors must hash to the producer's processor tensors, and the appended rows must be exactly the teacher tokens with mask 1 and text modality. Row `k` then becomes that input's last prefill row with `produces_generated_index` 0 and `reference_provenance.response_generated_index` `k`. No packager for such a manifest exists yet.

An `admission.json` must agree with `metadata.json` on inputs, runtime, response hash and the context fields that the producer fills in before running, and any directory entry the exporter never writes is refused. A greedy export (`greedy` metadata) or a BF16 or XPU export is refused; this importer covers unrestricted CPU FP32 teacher rows only.

## Conditioning and positions

The conditioning rows are the manifest's prompt rows `[token_id, t, h, w]` followed by the producer's own recorded teacher tokens after the prompt. That is all eight targets for a cached export and all 394 teacher tokens for the CPU214 forward, matching their recorded cache lengths. They are never native or CPU free-generated history. `write_dump` derives each record's consumed-prefix commitment from these rows. The importer then recomputes every commitment independently, authenticates the written dump with `load_dump`, and compares each payload byte for byte with its source row before the dump is renamed into place. A differing earlier token changes every later prefix, so a native decode step after its first divergence from the teacher is incomparable even where its current token coincides, and the comparator's conditioning summary names the first divergent generated index.

None of these producers captured three-axis positions, so every position in an import is source-derived and labelled `position_origin: source_derived` in each record and in the plan. The importer requires the manifest's position-source SHA-256 to equal the producer's recorded `model_source_sha256` (the pinned `modeling_qwen3_5.py`). It re-derives the prompt positions from the manifest's authenticated tokens, modality map, mask and grid with `prepare_input.positions` and requires exact equality with the manifest's position tensor, rope delta and next decode position. Rows after the prompt use the next decode position plus their offset on all three axes, which is the coordinate the native CLI and the exporter's cached formula both use. Matching positions in a later comparison therefore show agreement between derivations, not independent evidence of the CPU producer's internal positions.

## Commitments, attestation and producer identity

Before creating any output, the importer authenticates `metadata.json` against `--metadata-sha256` and streams the complete logits file once against the metadata's SHA-256, exact byte length, shape, little-endian float32 storage and 248,320-entry vocabulary. It authenticates the input manifest against `--input-sha256` and re-hashes every tensor, image and prompt file the manifest names. Before any tensor is read, each role must have its exact native input ABI from `ChandraNative/runtime/inference.cpp`: `input_ids`, `attention_mask`, `mm_token_type_ids` and the optional `text_position_ids` are I64 `[1, P]`, `position_ids` is I64 `[3, 1, P]`, `rope_deltas` is I64 `[1, 1]`, `image_grid_thw` is I64 `[1, 3]`, and `pixel_values` is F32 `[rows, 1536]` with 1 to 32,768 rows. Each also needs a byte extent of exactly its elements times the item size and contiguous `strides`, so a position tensor with another dtype, rank, shape, byte extent or stride is refused before its bytes are decoded. The byte extent and every stride must be JSON integers before their values are compared, because the native `unsignedNumber` reader refuses anything else: `96.0`, `9.6e1`, `[12.0, 1.0]` and `[true, true]` equal the expected integers under Python equality but are refused, as are byte extents above the native 268,435,456-byte descriptor limit and strides of 2^64 or more. The manifest's `image_token_id`, `positions.next_decode_position`, `image_token_positions` and `image_grid_thw` must hold JSON integers too. For the two lists this is stricter than the native reader, whose JSON equality also accepts integral floats there but never equates `true` with 1. The importer does not otherwise check native-only manifest fields such as `generation` or the image dimensions; the native reader remains their authority. It then requires equal tokenizer and config hashes (both also equal to the pinned processor files), image, prompt, processor profile, processed tensors, prompt tokens, model revision and modeling source. The runtime must be CPU `torch.float32` with Transformers 5.18.0.

The comparator joins only dumps whose `model_sha256` and `config_sha256` agree, and the producer metadata records no safetensors digest. A conversion therefore requires `--attest-model-sha256` equal to the pinned `provenance/model.json` safetensors SHA-256 together with a one-line `--attestation-basis`. The model line then records `model_sha256_origin: owner_attestation` with that basis next to `config_sha256_origin: producer_metadata`. Without the attestation a conversion is refused, and `--dry-run` reports the same commitment as missing. Optional `--producer-source` checks owner-supplied script bytes against `script_sha256` without executing or parsing them.

The producer kind is `transformers_cpu_fp32_teacher_export`. It deliberately does not begin with `cpu_`, so the comparator never reports `cpu_oracle_agreement` for an imported graph export, which is distinct from the CPU higher-precision operator oracle. The producer object binds the recorded runtime, response hash and the importer, comparator and packager source hashes. The commitments bind the source metadata and logits hashes and the route, and every record carries its source row, byte offset and producer absolute row in `reference_provenance`.

## Bounds, output and exit codes

All paths must be absolute, normalized and free of symlinked components. `--max-input-bytes` (at most 16 GiB) counts every byte read, and a stream that would exceed it is refused before reading starts. `--max-rows` is at most 64. `--deadline-seconds` (at most 7,200) is one monotonic deadline from process start, checked during every read, row, write and verification. The logits file is read once by complete rows into a fixed buffer, and only selected rows are kept. Symlinked, missing, truncated, oversized or growing files, unknown export entries, and malformed or duplicate-key JSON are refused. So is a JSON number that decodes to a nonfinite value. Python decodes an overflowing literal such as `1e999` to infinity, which the comparator's `strict_json` NaN/Infinity token check never sees, so every decoded number in the metadata, admission record and manifest must be finite, whether the importer ignores it, copies it into the dump or copies it into the report. Nesting deeper than 64 levels, and integers or nesting that Python's decoder cannot represent, are refused as well. Nonfinite words in a selected row are refused by default because the exporter refuses them; `--nonfinite preserve` keeps them unchanged as unqualified evidence.

`--max-output-bytes` (at most 256 MiB) bounds every regular-file byte any outcome writes under `--output` (directory metadata is the filesystem's), and it is enforced before the output directory exists. The importer serializes, one line at a time, the exact `progress.jsonl` that `compare_diagnostics.write_dump` will write, using the comparator's own key, observation and plan-hash functions. The forecast counts producer runtime and every other metadata value repeated in the plan line, in the plan's limitations and in every record; with the payloads it gives the exact reference bytes. Because this reproduces one writer, the importer pins the SHA-256 of `write_dump`'s source and refuses before output when it differs. It bounds the report by serializing it with every field settled after output creation at its longest form: status, a failure message (recorded messages are cut to 4,096 JSON bytes), the forecast comparator load, and the widest elapsed time, CPU time, peak RSS and output byte count. A conversion is refused with exit code 2 unless the exact reference bytes plus that report bound fit. This covers the imported outcome and every failure route, including a complete `unverified-reference/` beside its failure report. A dry run writes only its report and is refused unless that report's own bound fits. It reports `conversion_admissible` true only when it is attested and the forecast conversion of the same command without `--dry-run` also fits. The report's `forecast` object records `reference_bytes`, `report_bytes_bound`, `output_bytes_bound`, `conversion_output_bytes_bound` and `conversion_within_max_output_bytes`. After writing, the dump must equal its forecast in bytes and progress SHA-256, and `resources.output_bytes` records the measured bytes, the report itself included.

`--output` names a fresh directory created exclusively after authentication and forecasting. The dump is written into `unverified-reference/`, authenticated, compared byte for byte and checked against its forecast. Next, the acceptance report naming `reference/` is written and fsynced, and only after that, within the deadline, is the dump renamed to `reference/`. A `reference/` therefore never exists without a durable `import-report.json` that names it imported. If the rename fails or the deadline expires first, the report is rewritten in place as a failure. If the process is killed between the two steps, the report names `reference/` while only `unverified-reference/` exists, and the import must be treated as failed. Exit code 0 means imported and verified, or a dry run whose conversion is admissible as specified. Exit code 1 means a failure after output creation: the report states why, `unverified-reference/` remains if it was written, and if no report can be written at all, standard output carries it. Exit code 2 is a refusal before any output, with JSON on standard output, and it includes argument errors (option abbreviations are not accepted). Exit code 3 is a dry run whose conversion is not admissible as specified. The report records the command, source and input identities, recorded cache lengths, curated-evidence run identity, records with prefix and payload hashes, attestations, missing producer commitments, limitations, the comparator load result, the output forecast, elapsed time, input bytes, output bytes, peak RSS and false qualification claims.

## Commands

Use absolute owner-selected paths and the expected hashes; select an output directory under ignored `.local/` or `results/`.

```bash
python3 -I scripts/native/import_cpu_diagnostics.py \
  --export-dir "$CPU_EXPORT" --metadata-sha256 "$CPU_METADATA_SHA256" \
  --input-manifest "$INPUT_MANIFEST" --input-sha256 "$INPUT_SHA256" \
  --route cached-teacher-decode --rows 0,1,2,3,4,5,6,7,8 \
  --attest-model-sha256 0804568be9f099d6479fad9ed77a4da4611f3c1e7bc6e009af7dce45e8aa3847 --attestation-basis "$WEIGHTS_EVIDENCE" \
  --max-input-bytes 64000000 --max-rows 9 --max-output-bytes 16777216 --deadline-seconds 600 \
  --output "$FRESH_IMPORT_DIRECTORY"
python3 -I tests/native/test_import_cpu_diagnostics.py
```

A native dump that selects only full-vocabulary logits pairs every candidate record with an imported row. This plan selects the prefill row and the first eight decode steps; pass it with `--diagnostic-plan` and its SHA-256 to the explicit execution command in [the runtime guide](directcompute-runtime.md), then compare with explicit tolerances. Native decode steps pair with the imported cached rows only while native generated tokens equal the teacher targets.

## Tests and limits

The synthetic suite builds twelve-row prepared inputs and exporter-shaped directories with hand-derived positions. It checks exact preservation of random finite words and of signaling and quiet NaN payloads, signed zero and subnormals under `--nonfinite preserve`; prefill and cached decode phases, decode metadata and cache provenance; canonical prefixes recomputed by the test; sparse selection with unselected teacher rows still conditioning later rows; and an earlier native divergence that makes a later coinciding token incomparable. It also covers monolithic rows that stay prefill (including an extended manifest and both shorter- and longer-prefix refusals); route, source, profile, tokenizer, image, tensor, shape, dtype, position, hash and admission mismatches; truncation, oversize, orphan, symlink and partial-file refusals; ceilings, fresh output, the monotonic deadline and dry run; and a post-write verification failure that leaves no `reference/`. With a runtime string repeated in the plan, every record and the report, it runs dry runs and conversions at exactly their forecast ceilings and one byte below. At exactly the conversion forecast it also runs a verification failure, a failed rename with an oversized message, an unwritable acceptance report and no writable report at all, measuring every byte on disk and confirming that `reference/` never appears without its report. It refuses every role's wrong native tensor ABI, including the reviewed F32 text positions and four-byte rope delta, and wrong byte extents and strides. It also refuses, in conversions and dry runs, float, exponent and Boolean byte extents and strides for every role (including the three reviewed declarations), out-of-range extents and strides, and float or Boolean manifest image-token, grid and next-position integers. It refuses overflowing numbers in ignored, report-copied and record-copied fields, unrepresentable integers and nesting, in conversions and dry runs, along with argument, cache-name and writer-pin refusals. These checks run on the CPU and exercise no model.

An imported row is retained Transformers CPU FP32 evidence with an attested weights commitment and source-derived positions. Agreement or disagreement with it establishes neither complete CPU or AMD OCR, native numerical qualification nor throughput. Comparing CPU214 rows after the prompt requires either an extended prepared input with a native prefill on it, or a new cached teacher-decode CPU export reaching the needed step; both are root-owned.
