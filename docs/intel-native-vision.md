# Resolve native vision attention before further GPU trials

The normal-page B1 trial and a narrower diagnostic both reported device loss, with temporally correlated Windows engine-timeout archives. The diagnostic reached text-mask preparation before failing a synchronization; it never entered the first text layer. That identifies where the error surfaced, not the causal kernel. All test-owned processes subsequently closed and the ordinary endpoint returned cold. No full native-page inference or Intel speedup is qualified.

The pinned XPU selector has a material admission risk: an enabled `EFFICIENT_ATTENTION` branch can select math even when explicit math is disabled. The serving context also permits the oneDNN `OVERRIDEABLE` backend, which has higher default priority; its actual selection and workspace were not captured. The retained stderr has no efficient-fallback warning, so the source finding does not establish an observed fallback. [Pinned selector](https://raw.githubusercontent.com/pytorch/pytorch/5c4886908584029761b579af026dcfb627c84070/aten/src/ATen/native/mkldnn/xpu/Attention.cpp), [oneDNN bridge](https://raw.githubusercontent.com/pytorch/pytorch/5c4886908584029761b579af026dcfb627c84070/aten/src/ATen/native/mkldnn/xpu/detail/Attention.cpp).

The stock Torch build requests oneDNN 3.12.3 for XPU. That version tries a specialized SDPA primitive, then can fall back to a general partition of operators. The general path plans storage for complete intermediate tensor descriptors, including Torch's FP32 attention scores. A single supported graph partition therefore does not prove fused execution or bounded workspace. The same version includes XeHPG head-dimension-64 microkernel configurations, so this source evidence also does not establish that the A770 always uses the general path. The installed wheel's oneDNN build and actual internal dispatch remain unobserved; Torch's public backend selector alone cannot resolve them. [Torch dependency](https://raw.githubusercontent.com/pytorch/pytorch/5c4886908584029761b579af026dcfb627c84070/cmake/Modules/FindMKLDNN.cmake), [oneDNN dispatch](https://raw.githubusercontent.com/uxlfoundation/oneDNN/6db5f1ba860ca8f65c3f65c4498ad867e9642447/src/graph/backend/dnnl/kernels/sdp.hpp), [memory planning](https://raw.githubusercontent.com/uxlfoundation/oneDNN/6db5f1ba860ca8f65c3f65c4498ad867e9642447/src/graph/backend/dnnl/passes/memory_planning.cpp), [microkernel configurations](https://raw.githubusercontent.com/uxlfoundation/oneDNN/6db5f1ba860ca8f65c3f65c4498ad867e9642447/src/gpu/intel/sdpa/configs.cpp).

Flash-only would not provide an assumed remedy: the pinned Flash architecture whitelist omits Alchemist, the A770 architecture. The existing query-chunk candidate intercepts text attention; vision still uses full-image attention across 24 blocks. [Flash gates](https://raw.githubusercontent.com/pytorch/pytorch/5c4886908584029761b579af026dcfb627c84070/aten/src/ATen/native/transformers/xpu/sdp_utils.cpp).

These calculations use 16 heads. Native attention requires about 262 times Tiny's attention arithmetic. A possible 11.60 GB score buffer would accompany approximately 9.18 GB of live model allocations; neither the buffer nor the actual peak was observed. One-second resource samples cannot exclude brief workspace peaks. Fencing between whole vision blocks does not cap one attention call's memory or duration.

The first-vision diagnostic records the actual Q/K/V descriptors and queries the backend selector, then stops before invoking SDPA. Its preceding projection work still needs admission. The query-only candidate retains all keys, values, pixels, scaling and output allowance, with completion fences between calls. The smaller per-call score plane is a preparation bound, not proof of numerical equality or safety. Tiny numerical and complete-output checks, native-geometry primitive checks, clean process closure and independent admission precede any whole native-page retry. Both remain uninstalled source preparation. The [evidence index](../benchmarks/evidence/hillclimb-2026-10-04.json) records source commitments and keeps these findings separate from GPU acceptance.

The Q32 successor passes 15 bounded CPU tests of its equation, guards and ownership. On the small synthetic case, stock and Q32 have the same maximum error against an independent FP64 row reference and nearly identical RMS errors. Q32 differs from stock at one of 66,560 BF16 output elements, by 0.0001220703125; the original exact-comparison failure is retained. Row partitioning preserves the mathematical operation while allowing different floating-point rounding. These observations support a separately identified GPU experiment, not a production tolerance or trained-model accuracy claim. Tiny must still pass the existing full-vocabulary numerical policy and freely generated token, HTML, geometry and EOS checks before native qualification proceeds.
