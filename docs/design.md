# Chandra OCR 2 through DirectCompute

The implementation target is a native C++/HLSL Chandra OCR 2 runtime using DirectCompute and D3D11 in this Const-me/Whisper fork. NorthStone's AMD Radeon RX 7900 XTX endpoint is the primary end-to-end reference for complete OCR and sustained page throughput. An independent CPU higher precision operator oracle supplies the numerical reference. The Intel PyTorch XPU endpoint remains a historical functional reference with **0% qualified inference-engine speedup**; it is not completion of the native target, and XPU or OpenVINO performance work is outside the current scope.

## Model and workload

The checkpoint remains `datalab-to/chandra-ocr-2` at `af93b47dba1b47b6640c86ccf487ed2260ab9a09`, with the exact files authenticated by [the model manifest](../provenance/model.json). Its Qwen3.5 graph contains a vision encoder, 24 Gated Delta Net text layers and eight full-attention text layers. Preserve the 16,384-token context, normal 12,384-token output allowance, original prompt, tokenizer, processor profile and page pixels. The retained native/scanned page1 study uses 1,632×2,112 pixels and 3,959 prompt tokens. A changed processor profile, image size, precision or checkpoint creates a separate candidate requiring fresh qualification.

BF16 weight storage, explicit activation rounding and FP32 recurrent state are part of the candidate's arithmetic contract. The safetensors file stores both the input embedding and output head; storage sharing requires actual byte equality. The native importer authenticates the pinned payload and shapes before uploading bounded shards, verifies the two tensors' bytes, and omits unused MTP weights from the inference upload. These checks establish what is loaded, not whether the graph computes correct OCR. See [the native runtime contract](directcompute-runtime.md) and [importer source](../ChandraNative/runtime/model_weights.cpp).

## Native execution and references

Whisper's speech graph cannot execute Chandra by changing a model name. Its [D3D11 infrastructure](../Whisper/D3D) supplies the architectural starting point for explicit resource ownership, shader dispatch and staging readback. New Chandra code lives under [ChandraNative/runtime](../ChandraNative/runtime) and [its HLSL directory](../ChandraNative/shaders/runtime): a device and buffer API, model-weight importer, shared operators and a text graph with request-owned caches. The connected CLI already includes complete vision forward, ordered image-language merge, text prefill and cached greedy generation from authenticated preprepared tensors. Native image preprocessing, tokenization/detokenization, endpoint integration and full numerical/OCR qualification remain pending. Source or shader compilation is not a full-model result.

The AMD reference executes the exact model and conditioning through the existing ROCm endpoint. Retain its full response, token sequence, EOS, markup, content and resource observations for each comparison; its output is evidence rather than the sole ground truth. The CPU operator oracle evaluates identical prepared operands and continuously carried state in higher precision. [The existing C++ oracle](../ChandraNative/oracle.h) provides independent FP32 and double recurrence calculations; coverage for additional native operators must be established as they are implemented. [Historical full-model CPU comparisons](../verification/README.md) use FP32 and remain separate from this higher precision operator role.

## Correctness before throughput

Qualification progresses from authenticated imports and operator outputs/state, through complete recurrent and attention layers, vision and merged embeddings, to full-vocabulary logits in prefill and cached decoding, then freely generated complete OCR. Preserve BF16 cast boundaries, causal masks, three-axis M-RoPE, convolution histories and independently owned recurrent/KV state. Compare carried state without resetting it from reference checkpoints. Exercise repeated requests, interleaving, unequal completion lengths, cancellation, drain and resource reclamation. A local primitive pass or selected teacher-forced token agreement cannot qualify the full graph.

Only a complete, numerically qualified native path enters sustained throughput comparisons against the AMD reference. Measure correctly completed pages divided by the complete sustained measured interval in one loaded worker, including image preparation, transfers, fresh vision, prefill, decode and completion work. Record cold load and excluded prime/warmup separately. Sweep safe concurrency, repeat promising points and measure adjacent concurrency before calling a plateau or gain. Keep output length, quality, memory and lifecycle results beside every timing. Repeated-page measurements must disclose repeated pixels; they do not establish novel-page throughput. The [benchmark workflow](../benchmarks/README.md) and [retained throughput method](sustained-throughput.md) provide the input and accounting routes; their earlier XPU observations remain historical.

## Serving and provenance

The eventual native worker retains model alias `chandra`, `/v1/models`, `/v1/chat/completions` and a non-waking health route. Capacity stays owned until GPU work has actually drained, including after cancellation; a submitted request is never replayed automatically. The separate router can select NorthStone or Waystone without changing their independent service configurations. [The existing service package](../chandra_service) and [operations guide](operations.md) describe the historical endpoint contract, not an already deployed DirectCompute backend.

The fork preserves Const-me/Whisper history at `1ce7399704d8bea92429fc429819d32991fe9152`, the original MPL-2.0 source license and upstream attribution. Model weights retain their supplied OpenRAIL license and stay outside Git. [The retained work history](work-record-history-2026-10-05.md), [native primitive evidence](../ChandraNative/README.md) and [endpoint evidence](../benchmarks/evidence/README.md) preserve successes, failures and their distinct scopes. Earlier D3D11 primitive runs and XPU OCR are useful references; neither qualifies the new native graph or a native page-throughput result.
