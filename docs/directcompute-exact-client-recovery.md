# Original Zotero page recovery

The original populated Zotero page now completes in the frozen native Build20 CLI and resident worker. Both use the recorded 1,624 × 2,100 RGB image, 3,617 prompt tokens, a 16,384-token context and the normal 12,384-token output allowance. Neither run limits generation to a diagnostic prefix. Both generate 556 IDs through caller EOS 248046, pass all 18 recorded content checks and contain the complete columns, equations, 16 table cells and final page marker. This accepts one original fixture at functional scope; it does not qualify the corpus, trained numerics or an endpoint. The [redacted evidence record](../benchmarks/evidence/directcompute-exact-client-recovery-2026-10-06.json) binds the retained raw artifacts and separate independent reviews.

The second original native page fails on the same frozen Build20 worker. Its first prediction selects token 52427 with a logit of 9.95×10^29; the next prediction ties all 248,320 vocabulary entries at zero. All 1,952 generated IDs alternate 52427 and 0, with no EOS and none of the 18 expected content checks. The finite deadline cancels the request at a safe checkpoint; it drains, retires to the resident model and leaves zero owned Job processes after closure. The [failure record](../benchmarks/evidence/directcompute-native-second-page-failure-2026-10-06.json) preserves the original input, raw commitments, numerical symptom and resource receipt. The cause is unassigned. This rejects the second page and holds corpus, endpoint and throughput promotion; the first fixture’s accepted functional observations retain their recorded scope.

Build20 adds a uniform group barrier after reading the shared maximum in the production text-softmax shader, before reusing that shared storage for the sum reduction. Strict MSVC/fxc compilation and independent bytecode inspection confirm one added barrier instruction. The source archive contains retained build inputs and historical evidence outside the compile inputs; it is not a pure Git archive. Existing fxc warnings remain recorded. The [barrier and regression source](directcompute-exact-input-correctness.md) now pass finished source review, strict Windows compilation and all 17 model-free A770 cases; the earlier recovery evidence retains its original source cutoff. The runtime service has not been deployed. These observations do not prove the barrier alone caused recovery.
