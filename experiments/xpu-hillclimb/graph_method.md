# XPU graph capability probe

The first execution found native graph recording/replay unsupported on the installed A770 runtime. This retained probe loads no model and patches no serving or graph function. Execute only after the coordinator grants an exclusive Waystone GPU lease, inside the existing authenticated run_channel Windows Job Object, with graph_deadline.py as an inner 60-second deadline. The outer channel must own cancellation, SSH-disconnect cleanup and a deadline longer than the inner deadline plus its 30-second kill wait. A plain SSH launch is not acceptable ownership.

Supply two to four hashed trained recurrence fixtures from different cached positions of the same layer. The fixtures must include query, key, value, g, beta, initial_state and the original eager reference_output/reference_state; prefer the separately saved reference fixtures to exclude compiled candidate arrays. Source parity requires the exact approved modeling_qwen3_5.py SHA256 and the installed torch/xpu/graphs.py SHA256, both hashed directly on Windows. The Torch version and wheel commit are fixed to 2.14.1+xpu / 5c4886908584029761b579af026dcfb627c84070 and oneAPI compiler 20260100. The leased UUID, discrete A770 device ID and Level Zero platform are checked before allocation. No missing input, changed source or unsupported capability becomes an eager fallback.

Argument shape: `python experiments/xpu-hillclimb/graph_deadline.py --seconds 60 --receipt NEW_PRIVATE_RECEIPT -- python experiments/xpu-hillclimb/graph_capability.py --fixture TRAINED_REFERENCE_0 SHA256_0 --fixture TRAINED_REFERENCE_1 SHA256_1 --graph-sha256 MODEL_GRAPH_HASH --torch-graphs-sha256 TORCH_GRAPH_HASH --device-uuid LEASED_UUID --output NEW_PRIVATE_DIRECTORY`. This command belongs inside the owned channel. The wrapper is not an independent ownership guarantee.

The probe extracts the undecorated fallback through the existing AST-preserving helper, warms and captures exactly that source under inference mode, then uses six device input copies and independently cloned output/FP32 state for every replay. Buffers and the capture graph belong to this one probe/layer. No pooled graph sharing, compiler, arithmetic fusion, model/cache object or live page state participates. Host fixture payloads are bounded to 16 MiB each and 64 MiB aggregate, batch one and one token, with identical signatures. Warmup uses disposable static state. Capture is on an explicit owned stream and replay/copies run on that same stream.

Acceptance requires exact output and FP32 state bytes against eager on unchanged inputs, repeated identical replay, different trained inputs, eight chained state updates and restoration of the original page state. The stored eager fixture output/state must also agree exactly with the replayed source; input mutation fails. Graph scratch outputs are copied so later replay cannot rewrite earlier retained output/state. Page reset tests the state restoration boundary only; it is not a full-model page-isolation test. Successful graph construction without all byte comparisons is not acceptance. No timing claim follows from this synchronizing diagnostic.

The finally block synchronizes before graph reset and buffer release, then collects task objects and empties the cache. A runtime hang or asynchronous driver failure is instead contained by the owned channel's outer deadline; preserve partial receipt/logs and classify failure. PyTorch's native recording branch applies to non-PVC devices in this wheel, but the 2.14 release performance statement names B-Series and newer. API presence therefore did not establish A770 support. A future passing probe would establish one trained recurrence capability, followed by all-layer and complete-model numerical/OCR/reset/cancellation checks before any serving proposal.

The first explicitly leased primitive execution verified the pinned runtime/graph source and three actual layer-zero reference fixtures from cached positions zero, 127 and 393, totaling 12,681,792 tensor bytes. After disposable eager warmup, capture_begin failed with `Device does not support graph record and replay feature (UR_DEVICE_INFO_GRAPH_RECORD_AND_REPLAY_SUPPORT_EXP).` The child exited unsuccessfully after 9.454 seconds, before the inner deadline. No replay, changed-input, chained-state or reset comparison ran; the result is unsupported capability on the identified installed A770/Windows runtime, not a numerical failure or a qualified graph implementation. No model was loaded and serving was unchanged.

The failure receipt records synchronization, graph reset, owned-buffer release and empty_cache. Allocated/reserved counters were not measured by this frozen probe, so zero bytes are not claimed. The outer owned channel terminated normally and an independent Windows process query confirmed that its child was absent. Private source snapshots, preflight hashes, fixture commitments, channel/deadline receipts and raw error logs remain retained. The exclusive GPU lease was released after that confirmation. No driver/runtime change, fallback graph implementation or further GPU run is authorized by this failure.
