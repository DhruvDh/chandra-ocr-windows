# Compiler-free zero-centered norm candidate

These isolated experiment tools support staged numerical qualification, with raw runs retained privately and no performance promotion. The installed graph commitment is `d0c8561d91e31e50d9a57b74196c5a7ad023e42ebe9f84004d0a535310879939`, measured from the actual locked Windows Transformers Qwen3.5 module. The candidate checks that complete source commitment and PyTorch `2.14.1+xpu`, then intercepts exactly 81 `Qwen3_5RMSNorm` instances: two per decoder layer, Q/K norms in eight full-attention layers and the final text norm. Gated RMSNorm is untouched, preserving its BF16 normalized-output/weight-product boundary before FP32 gate multiplication. No serving source or weights change.

`norm_candidate.candidate(model, mode="gain-only")` precomputes `1.0 + BF16_weight.float()` once and keeps the original `_norm(x.float())` graph, multiplication and final BF16 cast. Frozen eval/inference is mandatory. Each intercepted call checks original parameter identity and its tensor mutation version; replacement or mutation fails explicitly rather than using stale gain. Captured gain must be bit-equivalent to independently recomputing the same expression. Scope exit restores every original forward, including after a failure. This mode isolates an arithmetic-preserving opportunity before introducing a different reduction implementation.

`mode="fused"` additionally substitutes unweighted native FP32 `torch.rms_norm` for `_norm`, then performs the original separate FP32 gain multiplication and BF16 cast. Passing the gain directly into a fused weighted norm would risk changing a multiply/rounding boundary, so this candidate leaves that product outside the kernel. PyTorch 2.14.1's [native operator registration](https://github.com/pytorch/pytorch/blob/v2.14.1/aten/src/ATen/native/native_functions.yaml) provides `_fused_rms_norm` XPU dispatch, and its [RMSNorm route](https://github.com/pytorch/pytorch/blob/v2.14.1/aten/src/ATen/native/layer_norm.cpp) selects that operator for ordinary inputs. The candidate also requires the installed runtime to report an actual XPU dispatch kernel. Native dispatch availability is not numerical or performance qualification, and no runtime compiler is used.

The normal graph launches input upcast, power, mean, epsilon addition, reciprocal square root, normalized multiplication, weight upcast, gain addition, gain multiplication and output downcast. Gain-only removes the repeated weight upcast and gain addition: approximately 162 small launches per cached token across 81 norms. Fused replaces five core tensor operations with one native norm invocation, removing four additional operator calls per norm. If the locked native implementation uses one device kernel per small decode norm, the estimated combined reduction is 486 kernels per token; a two-kernel native norm yields approximately 405. These are source-based launch forecasts to check with a bounded trace, not measured kernel counts or a predicted speedup. Retained gain storage is approximately 681,984 FP32 bytes for the pinned widths. The baseline's approximately 2,740 decode kernels per token makes this opportunity material enough to qualify separately.

Capture wraps original model norms and retains trained inputs, weights, precomputed gains and original BF16 outputs from every applicable module at actual prefill and first cached decoding. It samples up to 16 deterministic rows per module/phase, giving 162 fixtures with payload and shape/dtype commitments. The actual forward scope supplies phase identity; Q/K head rows alone do not identify decoding. Capture copies to CPU synchronize and perturb execution, so this run supplies correctness fixtures rather than timings. The independent `norm_cpu_reference.py --fixtures $Captured --output $NewOracle` evaluates the FP32 row equations with NumPy, then rounds to BF16 using independent ties-to-even integer arithmetic. It checks payload commitments and requires all prefill/decode modules; it reports output differences against the trained XPU reference instead of inventing a tolerance. Gains require strict bit equality.

Capture explicitly uses one cached teacher step; full candidate tests explicitly use all 394 frozen teacher steps, retaining 395 conditional logit rows and every cache tensor at all 395 positions. Before the fused full-model run, execute `norm_operator.py --mode fused --fixtures $Captured --output $NewOperatorOutput` under its own bounded GPU lease and compare its 162 trained outputs with original captures and the independent CPU oracle. Fused operator measurements require review before that full-model run; no arbitrary tolerance is embedded.

Gain-only must produce bit-identical trained norm outputs and full exported logits/cache tensors relative to a freshly pinned hybrid baseline, with actual interception counts covering all 81 modules. Fused norm may change FP32 reduction order, epsilon addition implementation or reciprocal-square-root rounding; those effects require trained operator comparisons, full-vocabulary cached/full equivalence, complete teacher-forced comparison and full greedy OCR/geometry checks. Both variants must preserve finite FP32 recurrent states, proper long-output EOS termination, all three frozen PNG gates and original output allowances. Only then compare repeated unprofiled warm requests against the same frozen hybrid baseline. Cancellation/state isolation remain promotion gates. The numerical wrapper's receipt records modes, source hashes, actual per-module calls and restoration; graph commitments are source checks, not independent remote process attestation.
