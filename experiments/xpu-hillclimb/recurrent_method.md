# Single-token compiled recurrence candidate

This experiment specializes the installed Qwen3.5 reference recurrent function to the existing one-token cached decoding calls. It extracts the exact function AST from the approved installed source, removes only the hub decorator and compiles it with Inductor, fullgraph enabled and dynamic shapes disabled. The model still constructs queries, keys, values, decay, beta and the trained initial state; normalization, scaling, update and readout come from the unchanged source. State remains FP32 and outputs retain BF16. This preserves the source arithmetic but compiler fusion and reduction ordering may change numerical results; it does not promise bit equality or a qualified speedup.

The installed decode path reaches this global function only for one-token calls with previous state; prefill and complete uncached teacher forcing use the chunk function. The numerical exporter enters the candidate scope before model construction. The prepared OCR harness enters it after model loading; that separate interception boundary remains unexercised and can be accepted only when its actual full-output call counts prove coverage. Its receipt counts every intercepted call and records the shape set. Zero interception is an error. For complete greedy output of N generated tokens, the expected count is 24 * (N - 1), because the prefill forward predicts the first token. Check this explicitly before accepting timing or correctness evidence; partial interception is not a full-model candidate. A hub kernel or a decorator that stores a separate function could bypass the patch, and must be treated as failed interception rather than a speedup.

No GPU work is authorized by this document. Run only with the coordinator's explicit exclusive lease. Every invocation must run through `scripts.host.manage.run_channel` and its outer `scripts/host/windows_lease.py` Windows Job Object, authenticated heartbeat and kill-on-job-close boundary; `recurrent_deadline.py` supplies an inner child-tree deadline and log receipt but is insufficient by itself for interruption or SSH disconnect. Begin with `recurrent_run_export.py --graph-sha256 <approved-installed-source-hash> --compile-cache <new-project-owned-AppData-runtime-cache> --fixture-limit 24 -- --device xpu --attention hybrid --model .runtime/model --image benchmarks/inputs-v2/tiny.png --prompt benchmarks/prompt.txt --response <qualified-tiny-response> --output <new-private-evidence-directory> --steps 1 --check-cache-equivalence`. Confirm the fixture filename against the checked corpus before invoking. This is a bounded compiler-capability and trained-input test, not a throughput measurement. Cold compilation may fail on the installed Windows toolchain; preserve that failure and do not install or upgrade global tools. The wrapper sets Inductor and Triton caches only in its own process under the supplied new directory, allowing an AppData NTFS cache if ReFS DLL loading is a problem.

Every captured trained call retains raw expanded-head Q/K/V, decay, beta, trained FP32 initial state, exact eager-source output/state and compiled output/state in a hashed safetensors file. The receipt records maximum absolute error, RMS error and bit equality for both outputs and states and rejects nonfinite tensors. The first 24 calls span all linear-attention layers at the first cached position. Increasing the fixture limit samples later positions too. These are actual model activations, not synthetic substitutions. Differential collection runs reference and candidate and synchronizes; its total cannot be used as performance evidence.

If capability and trained-state checks pass, compare an unchanged hybrid export against the candidate with identical pinned input and response bytes using `--steps 394 --check-cache-equivalence`, or the exact response-body token count recorded for that page. This visits every cached conditional distribution and retains cache records throughout. Use `verification/compare_exports.py` for full vocabulary distributions, greedy choices and margins. Retain the final candidate cached-versus-uncached result and compare it with the qualified baseline. The wrapper deliberately rejects `--all-teacher` and `--full-teacher`: those full-sequence paths do not execute the optimized one-token function. A separate unchanged complete teacher-forced result can establish the common prefill/uncached boundary but cannot qualify the new recurrence.

Only after these gates, run complete greedy OCR under the normal 12,384-token allowance and compare text, ordered blocks, table associations, equations, geometry, terminal token and completion count against the qualified baseline and CPU reference. Run all frozen PNGs before promotion. Collect warm repeated representative-page timing in an unprofiled scoped backend runner with fixture capture disabled and identical client logging, preserving complete output and interception counts. Separate compilation, loading and cold execution from warm latency; record model/runtime/source/input hashes and memory observations. The highest-value next decision remains measured profile attribution: this candidate is prepared, not selected or promoted merely because recurrence looks launch-heavy.

`recurrent_run_ocr.py` is a prepared unprofiled complete-output harness for `hybrid`, `recurrent`, `norm-gain`, `norm-fused`, `recurrent+norm-gain` and `recurrent+norm-fused`. It uses the unchanged backend's actual generation thread and normal 12,384-token allowance, records raw streamed text, complete token IDs, usage, terminal stop, frozen processed tensors, model verification, source hashes and memory, and checks exact interception counts of 24 * (N - 1) recurrent calls and N calls for each of 81 applicable norms for N generated tokens. Candidate contexts restore before unload; generated GPU tensor references are dropped, GC/synchronization/empty-cache run, and nonzero allocated/reserved memory fails the run. No activation capture, profiler or per-step device synchronization is added to measured generation. Raw token readback and OCR comparison happen after the generation timer stops. Buffered JSON event writing remains in the timer and is identical for baseline and candidate; these measurements are not zero instrumentation. Frozen manifest schemas select only the repository's original corpus validator or its independent qualification-v1 validator; the selected validator source hash and independent semantic/layout observations are retained separately from exact HTML timing comparability.

Each invocation selects one implementation in one owned process. Paired alternating comparisons use separate invocations and fresh private output directories, with `--baseline-summary` and `--baseline-response` from a successful unchanged harness run to attest identical request, processed tensor and response provenance. The runner reports geometry separately and marks timing comparable only with exact complete HTML, usage and stopping agreement plus content and interception gates; it never promotes a candidate. A differing but later accepted geometry measurement requires an explicit review outside this harness. `--warmups 1 --timings 0` collects complete correctness output without a warm timing claim. Recurrent modes require at least one complete warmup, which includes lazy compilation; helper initialization and model loading are measured separately. With zero warmups on another mode, the first request is explicitly not a measured warm run. For recurrent modes, initialize pinned Triton helpers through supported `triton.runtime.driver.active.get_current_target()` before compiling and before entering the backend generation thread; retain the helper/cache source identity and use the existing compiler's process-local `recurrent_compiler.cmd` environment. These preparation instructions do not authorize executing any candidate.

Bounded capability runs established that the existing MSVC toolchain can compile the pinned Intel Triton helpers without an installation or global environment change. Initial lazy helper compilation inside the Inductor invocation failed with Windows DLL initialization error 0xC0000142; reset child PATH/cwd, separate stderr and a clean compiler worker did not resolve that context. The exact retained helper source and compiler command compiled independently, including after XPU initialization. Supported helper preinitialization before `torch.compile` then completed actual trained fixture replay and a 24-layer one-token cached capability run. The latter intercepted all 24 linear layers, kept all captured inputs unchanged and retained expected shapes, BF16 outputs and FP32 states. Across those first cached calls, maximum output error against the uncompiled XPU source was 5.960464478e-8 (maximum RMS 9.331397877e-10), and maximum state error was 4.768371582e-7 (maximum RMS 1.824344009e-9); 18 of 24 BF16 outputs were bit equal. These are unqualified local operator observations. On identical complete-model inputs, prefill logits were bit equal to the retained hybrid reference but the first cached logit row differed by maximum 0.125 and RMS 0.0211054871, with the same greedy token. Independent CPU calibration, the full cached trajectory, later trained states and complete free OCR remain separate acceptance gates; no speed claim or serving promotion follows from compiler capability.

The complete recurrent-v1 cached trial was rejected by the frozen full-cached numerical policy v2 (SHA256 `c38b5e68de30daa925fcb416087453ec8b5c80c161a624d213caa1ad2051a5f4`). It retained all 395 conditioned vocabulary rows, intercepted exactly 9,456 cached recurrent calls, and sampled all 24 trained layers at cached decode positions 0, 127 and 393, with unchanged sampled inputs and finite logits/states. Six absolute prediction positions exceeded their reference-calibrated budgets: 806, 851, 924, 982, 1170 and 1174. Total variation and target-token log probability failed at 806, 851, 924 and 1170; total variation alone failed at 982 and 1174. Candidate versus matched CPU FP32 maximum total variation was 0.404834 (unchanged hybrid 0.379371), maximum target-token log-probability error was 0.959275 (hybrid 0.860880), and maximum KL was 0.434763 (hybrid 0.380477). Candidate CPU argmax agreement was 390/395, versus hybrid 394/395. At position 924 the CPU and hybrid chose digit `3` while the candidate chose `4`; this was an equation-block y1 bounding-box digit, outside the frozen full-cached exception set. All six failed contexts were bounding-box digits; no non-box conditioned argmax change was observed. Their location does not override the predeclared numerical and decision gates. The comparison receipt commits to SHA256 `1cd91349237ec59e26ada9ee582f9cb48d9a3fabbb302d2303786037496c7af5`, and its concise gate summary to `0940cce0c014e65b267c634b1a72631f0d6f5e2a47d3301f8b121d70079a7aeb`.

Independent CPU replay of all 72 sampled operator fixtures still found small FP32 state error: compiled-versus-CPU maximum 2.384e-7, versus uncompiled XPU-versus-CPU 4.768e-7. This local operator result is distinct from the failed coupled model trajectory. Recurrent-v1 was therefore set aside before free OCR or performance collection, and was never promoted. The generic OCR harness remains available for separately qualified candidates; its existence is not authorization to execute this rejected implementation.
