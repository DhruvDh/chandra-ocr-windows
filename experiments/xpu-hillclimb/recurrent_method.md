# Single-token compiled recurrence candidate

This experiment specializes the installed Qwen3.5 reference recurrent function to the existing one-token cached decoding calls. It extracts the exact function AST from the approved installed source, removes only the hub decorator and compiles it with Inductor, fullgraph enabled and dynamic shapes disabled. The model still constructs queries, keys, values, decay, beta and the trained initial state; normalization, scaling, update and readout come from the unchanged source. State remains FP32 and outputs retain BF16. This preserves the source arithmetic but compiler fusion and reduction ordering may change numerical results; it does not promise bit equality or a qualified speedup.

The installed decode path reaches this global function only for one-token calls with previous state; prefill and complete uncached teacher forcing use the chunk function. The numerical exporter enters the candidate scope before model construction. The prepared OCR harness enters it after model loading; that separate interception boundary remains unexercised and can be accepted only when its actual full-output call counts prove coverage. Its receipt counts every intercepted call and records the shape set. Zero interception is an error. For complete greedy output of N generated tokens, the expected count is 24 * (N - 1), because the prefill forward predicts the first token. Check this explicitly before accepting timing or correctness evidence; partial interception is not a full-model candidate. A hub kernel or a decorator that stores a separate function could bypass the patch, and must be treated as failed interception rather than a speedup.

No GPU work is authorized by this document. Run only with the coordinator's explicit exclusive lease. Every invocation must run through `scripts.host.manage.run_channel` and its outer `scripts/host/windows_lease.py` Windows Job Object, authenticated heartbeat and kill-on-job-close boundary; `recurrent_deadline.py` supplies an inner child-tree deadline and log receipt but is insufficient by itself for interruption or SSH disconnect. Begin with `recurrent_run_export.py --graph-sha256 <approved-installed-source-hash> --compile-cache <new-project-owned-AppData-runtime-cache> --fixture-limit 24 -- --device xpu --attention hybrid --model .runtime/model --image benchmarks/inputs-v2/tiny.png --prompt benchmarks/prompt.txt --response <qualified-tiny-response> --output <new-private-evidence-directory> --steps 1 --check-cache-equivalence`. Confirm the fixture filename against the checked corpus before invoking. This is a bounded compiler-capability and trained-input test, not a throughput measurement. Cold compilation may fail on the installed Windows toolchain; preserve that failure and do not install or upgrade global tools. The wrapper sets Inductor and Triton caches only in its own process under the supplied new directory, allowing an AppData NTFS cache if ReFS DLL loading is a problem.

Every captured trained call retains raw expanded-head Q/K/V, decay, beta, trained FP32 initial state, exact eager-source output/state and compiled output/state in a hashed safetensors file. The receipt records maximum absolute error, RMS error and bit equality for both outputs and states and rejects nonfinite tensors. The first 24 calls span all linear-attention layers at the first cached position. Increasing the fixture limit samples later positions too. These are actual model activations, not synthetic substitutions. Differential collection runs reference and candidate and synchronizes; its total cannot be used as performance evidence.

If capability and trained-state checks pass, compare an unchanged hybrid export against the candidate with identical pinned input and response bytes using `--steps 394 --check-cache-equivalence`, or the exact response-body token count recorded for that page. This visits every cached conditional distribution and retains cache records throughout. Use `verification/compare_exports.py` for full vocabulary distributions, greedy choices and margins. Retain the final candidate cached-versus-uncached result and compare it with the qualified baseline. The wrapper deliberately rejects `--all-teacher` and `--full-teacher`: those full-sequence paths do not execute the optimized one-token function. A separate unchanged complete teacher-forced result can establish the common prefill/uncached boundary but cannot qualify the new recurrence.

Only after these gates, run complete greedy OCR under the normal 12,384-token allowance and compare text, ordered blocks, table associations, equations, geometry, terminal token and completion count against the qualified baseline and CPU reference. Run all frozen PNGs before promotion. Collect warm repeated representative-page timing in an unprofiled scoped backend runner with fixture capture disabled and identical client logging, preserving complete output and interception counts. Separate compilation, loading and cold execution from warm latency; record model/runtime/source/input hashes and memory observations. The highest-value next decision remains measured profile attribution: this candidate is prepared, not selected or promoted merely because recurrence looks launch-heavy.

`recurrent_run_ocr.py` is a prepared unprofiled complete-output harness for `hybrid`, `recurrent`, `norm-gain`, `norm-fused`, `recurrent+norm-gain` and `recurrent+norm-fused`. Supported helper preinitialization before `torch.compile` then completed actual trained fixture replay and a 24-layer one-token cached capability run. The latter intercepted all 24 linear layers, kept all captured inputs unchanged and retained expected shapes, BF16 outputs and FP32 states. A distinct recurrent-v2 source-rounding experiment is staged in `recurrent_v2_candidate.py` and `recurrent_v2_run_export.py`; it has not executed on the GPU or passed any numerical gate. The recurrence AST, source operations, FP32 state and original fusion scheduling are unchanged. Installed Inductor `TritonKernel.triton_meta_common` explicitly emits `enable_fp_fusion = not config.emulate_precision_casts`, so setting only `TRITON_DEFAULT_FP_FUSION=0` would be overridden. This exact recurrence widens Q/K/V/beta/decay to FP32 before normalization, creates FP32 output storage and performs all recurrence arithmetic in FP32 until its terminal BF16 cast. Installed precision-emulation lowering reinstates truncation only for low-precision operation outputs; source inspection therefore supports `emulate_precision_casts=True` here without introducing new BF16 arithmetic boundaries. This is a source-based assessment that must be checked against actual generated code. Supported `torch.compile` options set `use_fast_math=False` and `emulate_precision_casts=True`; process-local `TRITON_INTEL_FAST_MATH=0` explicitly overrides its Inductor fallback. The pinned Intel backend calls `intel.set_fast_math(llvm_mod, metadata['enable_fp_fusion'], knobs.intel.fast_math)`. V2 uses hash-guarded observation-only hooks for emitted metadata and backend option parsing, fails if contraction or Intel fast-math remains enabled, records observation counts, and restores descriptors and environment. No compiler metadata override is used. A new cache is mandatory; absence of either observation fails successful execution. Retain generated code and actual compiler options and verify FP32 intermediates/final BF16 store. These controls are compiler-policy evidence, not a claim that all reassociation, reductions or transcendentals match eager arithmetic.
