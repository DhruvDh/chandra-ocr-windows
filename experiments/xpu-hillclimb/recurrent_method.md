## What the candidates change

[recurrent_candidate.py](recurrent_candidate.py) extracts the exact installed Qwen3.5 recurrent fallback AST, removes only its hub decorator, and compiles the source function with Inductor, fullgraph enabled and static shapes. It specializes only one-token cached decoding with an existing recurrent state. Queries, keys, values, decay, beta and state still come from the trained model. Arithmetic and persistent state remain FP32 until the original BF16 output boundary. Prefill continues to use the original chunk function. Compiler fusion, reduction order and transcendental implementations can nevertheless alter rounding.

The candidate patches the installed global function within an owned scope and restores it afterward. Each cached token should intercept all 24 linear-attention layers. A greedy response of N tokens therefore requires 24 × (N − 1) calls: prefill predicts the first token. The complete conditioned trials each retained 395 vocabulary rows, 9,456 interceptions and 72 trained fixtures spanning all 24 layers at decode positions 0, 127 and 393. Every fixture contains hashed actual inputs, eager output/state and compiled output/state. Inputs must remain unchanged and all state must remain finite FP32. Capturing both implementations and copying fixtures to CPU perturbs execution; these durations are validation evidence, not speed measurements.

[recurrent_v2_candidate.py](recurrent_v2_candidate.py) retains that source and scheduling while selecting supported `torch.compile` options `use_fast_math=False` and `emulate_precision_casts=True`. In the pinned Inductor source, the latter disables emitted `enable_fp_fusion`. Setting the Triton environment default alone would be overridden. Source and generated-code inspection found FP32 intermediates and the original final BF16 store, with no new BF16 truncation boundaries. Observation-only hooks verify emitted metadata and Intel backend options; exact installed compiler-source hashes are pinned in the candidate. A fresh cache and positive observation counts are required, and descriptors/environment are restored afterward.

The retained compiler output confirms a real policy change: v1 contained 606 LLVM contraction flags across 15 IR files, while v2 contained none. Both collections still contained 380 explicit SPIR-V FMA calls inside the exponential library approximation. Disabling contraction therefore does not make the fused computation identical to eager arithmetic. The Intel backend's [official documentation](https://github.com/intel/intel-xpu-backend-for-triton) and [compiler source](https://github.com/intel/intel-xpu-backend-for-triton/blob/main/third_party/intel/backend/compiler.py) distinguish these controls; the trial relies on exact installed source commitments rather than a moving online branch.

## Run a bounded diagnostic

Use the project's authenticated Windows Job Object channel and an exclusive GPU lease, with the ordinary worker stopped. The inner [deadline helper](recurrent_deadline.py) bounds its child but requires the outer ownership boundary to clean up after coordinator interruption. Retain immutable source, model, runtime, input, policy and output commitments before interpreting a result. Every run must confirm the owned process is absent before releasing the lease.

The existing MSVC installation can compile the pinned Intel Triton helpers. Early attempts failed with `0xc0000142` when helper compilation happened inside Inductor; changing PATH, working directory or compiler subprocess plumbing did not resolve it. Calling the supported `triton.runtime.driver.active.get_current_target()` before compilation did. Keep that preinitialization, the process-local environment from [recurrent_compiler.cmd](recurrent_compiler.cmd), and a fresh project-local C-drive cache. No global compiler, PATH or drive-trust change is needed. Retained failed attempts remain diagnostics.

The entry points are [recurrent_run_export.py](recurrent_run_export.py) for v1 and [recurrent_v2_run_export.py](recurrent_v2_run_export.py) for v2. Their CLI accepts a retained `--replay-fixture` with its hash, or delegates to the ordinary numerical exporter. Use `--fixture-limit 24` for all first-decode layers, and `--fixture-limit 72 --fixture-positions 0,127,393` for a full trajectory. Freeze the numerical policy and pass its expected hash; capability is not permission to loosen that policy. The tested all-layer and full-trajectory bounds were 180 and 600 seconds, respectively. Full trials retained approximately 1.55 GB each, including complete and partial logits and trained fixtures.

V2's first single-fixture receipt was written before scope exit and retained `restored=false`: the shared exporter had replaced `sys.argv`, preventing the wrapper's final rewrite. That raw receipt remains unchanged. The distinct v2 entry point now saves its original invocation and writes the receipt after scope restoration. Subsequent all-layer and full trials recorded restored controls, exact executed source identities and independently verified child absence. Metadata and hashes establish consistency of retained evidence; they do not independently attest remote execution.

## Complete OCR and timing remain separate

The prepared [OCR harness](recurrent_run_ocr.py) supports recurrence, normalization and baseline modes. It calls the actual backend generation path with the ordinary 12,384-token allowance, preserves complete token IDs, text, stop reasons, usage, processed inputs and source identities, and checks actual interception counts. It compares ordered content, table associations and geometry separately from exact output equality. Candidate scopes restore before unloading, and nonzero Torch allocated/reserved memory fails cleanup. This harness was not run for either rejected recurrence variant.

A future recurrence variant must first pass trained-operator and complete cached numerical checks under a prospectively frozen policy. Only then may complete OCR, cancellation, state isolation and paired warm timing establish a usable performance improvement. Compilation, fixture capture and numerical export must remain outside performance measurements. The current serving implementation continues to use the qualified original recurrence.
