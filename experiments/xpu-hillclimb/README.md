# Improving Windows OCR performance

Current work targets Intel’s highest safe sustained pages per second at OCRd’s actual image conditioning and output allowance. The latest H3 AB run passed independent complete-output, finite state-isolation, runtime/resource and closure review for four outputs: two normal, one Tiny, and repeated native. It completed 949 B2 and 161 B1-tail forwards and restored the service cold. This bounded AB result does not establish normal full-vocabulary equivalence, BA behavior, a matched timing gain, sustained throughput, full CLI or deployment. Its 512.797-second diagnostic is about 4.47% longer by arithmetic than prior FFN AB/BA observations, but the trials are unmatched and no performance result is accepted.

The combined GDN input-projection plus FFN row-geometry candidate separately passed its frozen Tiny/Small teacher-forcing numerical gate in AB and reversed BA order, matching 710 full-vocabulary rows and 45,440 primary state fields exactly in each. Four inherited target-versus-winner departures remain; this does not qualify free-greedy OCR. The earlier normal-size FFN B2 OCR candidate and accepted E6 B1 native/scanned cases remain separate. No Intel speedup has been accepted.

CLI04 passed source review but failed actual qualification when heartbeat publication raised WinError5 and the guard reported failure. Independent review verifies owned-process closure and cold restoration; complete CLI output and formal cleanup remain unqualified. The guard-reader repair and native file-I/O probe precede further GPU trials. A separate direct engine benchmark will compare serial inference and FFN batching at the accepted client conditioning; full CLI acceptance remains required before serving deployment. The lifecycle import defect has a source-reviewed repair, with actual behavior still pending. See the [current work record](../../docs/work-record.md) for these boundaries and the retained failures.

Before any later GPU trial, follow the [numerical gates](../../verification/hillclimb-numerical-gates.md), establish an appropriate work window and exclusive GPU lease, and run through the project's owned Windows Job Object channel. Stop the ordinary Windows worker only for the duration of that owned trial and restore its qualified on-demand service afterward. Do not change host drivers or run stress, deliberate crash, custom-kernel or compilation experiments during concurrent priority work.

An earlier 3,617-token representative-page experiment completed correctly with 397 output tokens; it predates the current exact 3,959-token conditioning. Its separate unprofiled warm request took 85.497 seconds; the instrumented request took 126.375 seconds. The trace covers one prefill and eight cached forwards and reveals approximately 2,740 GPU kernels per decoding token. Instrumentation substantially changes execution time, so it identifies opportunities without establishing an attainable speedup.

The [query-chunk candidate](query_chunk_attention.py) processes attention queries in chunks of 256 while retaining the full key dimension, unchanged pixels, output allowance and BF16 precision. Independent numerical and resource/closure review passed all 395 full-vocabulary logit rows and 25,280 ordered cache-digest records; the ordinary Windows worker returned cold. This is exact numerical evidence, not raw cache-tensor replay or a measured speedup. The subsequent five-page OCR result is recorded below.

The guarded AMD shared-S2 pilot passed initial idle admission and its excluded tiny-page quality check, then stopped during the first C1 warmup when free VRAM fell to 3.931896 GiB, below the unchanged 4 GiB floor. Available RAM stayed at least 32.837 GiB and backend drain was verified. No measured cell or C2/C4 run completed, so no throughput ceiling or speed result is established. A subsequent 65% GPU-budget plan remained source preparation. AMD throughput tuning was then cancelled under the revised scope; that plan will not run.

The query-chunk-256 composition subsequently passed all five complete OCR pages with exact retained outputs and equality to reference token IDs wherever those IDs are available; historical unavailable IDs remain unavailable. Independent acceptance verifies 40 multi-query prefill attention calls, 312 query chunks, 18,424 cached delegates and 2,303 cached model calls. Across 554 resource samples, minimum process-local headroom was 4,586,340,352 bytes (4.27 GiB) and minimum available host RAM was 16,883,732,480 bytes. All five owned processes ended and the ordinary Windows worker was restored cold. The earlier parent composition’s representative-page resource failure remains unchanged. This qualifies the frozen five-page regression scope, not dense-page GPU inference, sustained throughput, speed or deployment. A dense processor-fit check reaches 3,629 tokens; its GPU inference remains pending.
