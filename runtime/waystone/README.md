# Intel XPU reference runtime

This environment pins official stable PyTorch 2.14.1+xpu, torchvision 0.29.1+xpu, Triton XPU 3.8.0, Transformers 5.18.0 and Chandra 0.2.0. `uv.lock` preserves exact package URLs and download SHA256 hashes. Model weights are supplied separately at revision `af93b47dba1b47b6640c86ccf487ed2260ab9a09` and the backend hashes nine critical weights/config/processor/tokenizer/template files against `provenance/model.json` before first GPU allocation. It caches verification only while file stat signatures remain unchanged and reports verification time separately. The source manifest records 17 downloaded files; the retained Windows transfer contains 15 critical/support files, omitting the two hidden metadata files. `scripts/waystone/verify_model.py` can verify the transferred set independently.

Run `scripts/waystone/install.ps1 -Uv <existing-uv.exe> -Python <existing-python.exe>` from PowerShell. The installer copies the existing Python installation and creates an isolated environment under `%LOCALAPPDATA%\chandra-ocr-windows\runtime`; override `-RuntimeRoot` to select another task-owned physical path. No global package, PATH or driver settings are changed. Source and model directories may remain on a Dev Drive. Use the resulting `.venv\Scripts\python.exe` directly, with the repository as the import root.

`bootstrap.prepare_runtime()` loads the locked environment's Intel/PyTorch DLLs by absolute path in dependency order, adds their directories to the process's DLL search and PATH, and selects `level_zero:gpu` unless the operator already set a selector. This addresses observed Windows dependency-search failures and XPU enumeration crashes without modifying DLL bytes or machine drive trust. The wrapper is specific to this lock; missing DLLs fail explicitly. Installation alone does not qualify a machine: run `scripts/waystone/xpu_probe.py` before model inference.

`XPUBackend(model_path, attention_backend="eager")` offers lazy `load()`, read-only `health()`, incremental `generate(request, cancel)` and idle-only `unload()`. Generation accepts the validated single-image OpenAI request shape, yields decoded text deltas and then a final usage/finish-reason dictionary. It preserves incoming RGB pixels and prompt text before the model processor, runs explicit BF16 on XPU with no CPU fallback, and holds its generation thread until cancellation actually stops execution. Unload releases resident weights and cached allocations; the next request performs a cold load.

The processor profile is explicitly `size={"shortest_edge":3136,"longest_edge":3145728}`, matching the established comparison endpoint. Defaults limit processed prefill to 4,096 tokens and permit 16,384 combined input/requested-output tokens and at most 12,384 requested output tokens, with a four-million-pixel decode admission bound. Requests exceeding these limits fail rather than crop or truncate silently. Eager attention additionally rejects more than 4,096 raw vision patches to protect memory. The serving CLI defaults to `attention_backend="hybrid"`, which explicitly selects vision SDPA and text eager attention and asserts both selections. The dense math SDPA backend is disabled to prevent an unintended quadratic-memory fallback. All-SDPA text decoding failed cached-logit and complete-page checks on the tested runtime; it remains diagnostic only. Hybrid passed all three frozen direct-backend OCR fixtures once; service transport and sustained performance remain separate gates. The loader skips only Transformers' best-effort model-sized allocator warmup, because its contiguous 8.46 GiB reservation failed on the tested Arc; individual unchanged parameter allocations succeed.

The initial A770 smoke ran the pinned model on a synthetic 512×256 page using eager attention and returned all three expected text lines including `Total: 123.45`. Load took 13.60 seconds and generation took 27.61 seconds for 116 completion tokens; peak Torch allocation was 9,453,229,056 bytes. This proves bounded reference execution, not numerical equivalence to another runtime, larger-page admission, sustained performance or production qualification. Transformers used its reference PyTorch causal-convolution and gated-delta-rule kernels on XPU because optional optimized kernels were absent. Retain raw numerical, endpoint and performance evidence outside Git.

Reproduce the hybrid checks from the repository root with the installed environment Python (shown as `$Python`), a verified model directory `$Model`, and task-owned output directories. The processor and attention profile are explicit in every retained run.

```powershell
& $Python scripts/waystone/run_export.py verification/export_logits.py --model $Model --image benchmarks/inputs-v2/tiny.png --prompt benchmarks/prompt.txt --response $TeacherResponse --device xpu --attention hybrid --check-cache-equivalence --output $CachedOutput
& $Python scripts/waystone/run_export.py verification/export_logits.py --model $Model --image benchmarks/inputs-v2/tiny.png --prompt benchmarks/prompt.txt --response $TeacherResponse --device xpu --attention hybrid --all-teacher --output $TeacherOutput
& $Python scripts/waystone/corpus_reference.py --model $Model --inputs benchmarks/inputs-v2 --prompt benchmarks/prompt.txt --attention hybrid --case tiny small representative --output $CorpusOutput
```

`$TeacherResponse` is the retained frozen baseline response; it is supplied separately from public source. `hybrid-summary.json` records all three bounded page results and numerical limitations; [the numerical evidence](../../verification/evidence/README.md) connects them to the CPU oracle and excluded SDPA path. The corpus runner retains original response bodies, incremental timing events, exact source/input hashes, actual usage, verification timing and peak Torch allocation outside Git. Run `benchmarks.endpoint.validate` on each result against the frozen fixture's `expected` object; generation completion alone is not an acceptance gate.
