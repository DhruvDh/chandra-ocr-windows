# Recorded synthetic CLI preparation fixtures

These four original request JSON files are the authenticated recorded requests for the repository's two-page public synthetic CLI corpus, in native-text and scanned variants. Their embedded PNGs contain invented measurement tables, two prose columns, simple equations and page-end markers. They contain no research documents, Zotero records, credentials, endpoint addresses or machine paths. All four files together occupy 1,378,896 bytes. The test reads them directly from this directory and needs no retained task files, tensor arrays, font installation, PDF renderer, model or network access.

The synthetic content is CC0-1.0, as declared by [the source corpus manifest](../../../../benchmarks/cli-inputs-v1/manifest.json). The original generator is [benchmarks/generate_cli.py](../../../../benchmarks/generate_cli.py), SHA256 `ce2c186b8f74acea4a53e8c87c24b84c08102be482b8b9c6d89dcc4694a239fa`; its manifest is `533279f4b7f73ca69800d2b8f273496463afa1cb123c1b84521fdac66403edd1`. The DejaVu font notice is copied unchanged from `benchmarks/DejaVu-LICENSE.txt` to [DejaVu-LICENSE.txt](DejaVu-LICENSE.txt), SHA256 `7a083b136e64d064794c3419751e5c7dd10d2f64c108fe5ba161eae5e5958a93`. Only rasterized glyphs are included here; no font or PDF is duplicated. The preparation implementation's upstream licenses remain under [licenses](../../licenses).

The generator's initial 1,632 × 2,112 renders are not these inputs. The installed Chandra client's recorded `scale_to_fit` path produced the 1,624 × 2,100 RGB images retained in these requests. Their original encoded/RGB hashes were authenticated in `recorded-cli-cpu-inputs-01/corpus/manifest.json`, SHA256 `86317d2a06f1aff0a2956186475ff52bc34301e3419fc49b82059d1840677a67`. The request files are exact copies from `sol-native-sustained-throughput-harness-03/inputs`, without JSON reserialization. The recorded workload had 3,617 prompt tokens, context capacity 16,384 and an unchanged 12,384-token output allowance. This CPU test authenticates those recorded settings and requests; it does not tokenize or execute a model.

[expected.json](expected.json) freezes original request hashes and byte counts, prepared request hashes, and all deterministic preparation metadata, including original/prepared image hashes and dimensions. Prepared request commitments use UTF-8 JSON with `ensure_ascii=False`, separators `(',', ':')`, `allow_nan=False` and no trailing newline. Prepared PNG commitments include encoding bytes; RGB commitments hash decoded row-major RGB bytes. The expected manifest itself is pinned by SHA256 in the test. Original request commitments match the earlier test's fixed pins and the exact recorded copies. Prepared commitments and metadata were transcribed from the previously reviewed `package-test-01.json` receipt, SHA256 `0163832de48d3f2edc65d42f137d2ef89471dbab7fe535e1c21bdf535e8bc57e`, with nondeterministic timings omitted. They are frozen expectations, never regenerated during a test run.

The earlier `numpy-comparison-01/report.json` receipt, SHA256 `410ddd6afbd299c17bea7de7342a3173fd9414f8764d6f46d471779e82d88201`, established exact agreement with all four frozen CPU RGB arrays and full normalized/patchified FP32 tensors. Those large historical tensors and execution records remain local engine-trial evidence; they are not required for this regression and are not copied into the public repository. This finite synthetic regression checks preparation compatibility, not broad OCR accuracy, AMD input-tensor equivalence or engine numerical acceptance.

From the repository root, with the pinned [requirements](../../requirements.txt) installed, run `python -m runtime.sycl.test_prepare`. All four cases run unconditionally alongside the small shape and invalid-input controls. An optional `--report /path/to/new-report.json` writes an exclusive new report; no existing file is overwritten. The tests never submit requests or update their fixtures.
