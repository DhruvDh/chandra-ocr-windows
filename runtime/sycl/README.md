# CPU image preparation for the SYCL candidate

This package prepares an original PNG/JPEG/WebP data URL for the pinned Qwen image processor profile without importing Torch, Transformers, model weights or a GPU runtime. It decodes with Pillow, applies the existing service's `convert("RGB")` semantics, selects the target with Qwen `smart_resize`, performs the exact retained uint8 antialiased bicubic resize using NumPy, and emits a lossless PNG. It starts no subprocess and makes no network request. Service, router and backend integration remain separate work.

```python
from runtime.sycl import prepare_image, prepare_request

image = prepare_image(original_data_url)
prepared_request, image = prepare_request(original_request)
# image.png, image.data_url, image.metadata
```

`prepare_request` returns a deep copy with only the single image URL changed. Omitted optional fields remain omitted, text/image order is preserved, and every non-image field retains its original value, including caller metadata. It checks the Chandra model alias, one user message, one text/image pair and the supported output-allowance range. It deliberately does not import the service application or replace full HTTP request validation; the caller still owns supported-field/stream/sampling validation, the 128 MiB HTTP-body bound, tokenization, complete context admission, request ownership and submission. Unsupported preparation inputs raise `PreparationError`, a `ValueError` subclass. Requested output allowances remain unchanged; the package never reduces them to make a request fit.

Original-image admission precedes resizing. The default decoded-pixel limit is 4,000,000; `max_image_pixels` may explicitly select an integer from 1 through 6,291,456, matching the existing native configuration range. The data URL itself cannot exceed the service's 128 MiB body bound, base64 must be strict/nonempty, actual bytes must match the declared PNG/JPEG/WebP media type, and animated/multiframe inputs are rejected. Pillow's decompression limits remain active. The package does not change Pillow globals or warning filters. It introduces no EXIF transpose, color management, crop or alpha compositing beyond the existing service's RGB conversion semantics.

Admission limits and processor geometry have different roles. The fixed processor profile uses factor 32, minimum 3,136 pixels, maximum 3,145,728 pixels and maximum aspect ratio 200. A valid original 1,624 × 2,100 page is therefore resized directly to 1,536 × 2,016; it is not cropped or padded. Raising or lowering the original-pixel admission limit never changes this profile. An image already at its selected target size preserves every decoded RGB byte. Metadata records original and prepared dimensions, encoded/RGB SHA256 values, byte counts, admission/profile values, dependency versions and resize/total timings.

Use the existing environment with [requirements.txt](requirements.txt): NumPy 2.5.3 and Pillow 12.3.0. The implementation refuses a different version instead of silently changing this qualified candidate. The observed Linux runtime is Python 3.12.14. Exact Windows-wheel equivalence and broader arbitrary-document numerical qualification remain separate from the finite Linux input regression. These constraints establish no model or endpoint acceptance.
