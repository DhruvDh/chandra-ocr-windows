# Native Chandra OCR for Windows

This public fork of [Const-me/Whisper](https://github.com/Const-me/Whisper) preserves its history and MPL-2.0 source while developing Chandra OCR 2 inference for Windows Intel GPUs. The objective is correct, complete OCR at the best sustained concurrency, measured against an empirical hardware roofline. NorthStone's AMD Radeon RX 7900 XTX endpoint is the primary end-to-end reference; independent CPU higher precision calculations are the operator oracle. The original project documentation remains in [WHISPER-README.md](WHISPER-README.md).

The [frozen recovery/PDF evidence](benchmarks/evidence/sycl-q8-c5-driver-9150-recovery-2026-10-17.json) and [work record](docs/work-record.md#current-work) retain compatibility, lifecycle and qualification limits; no experimental kernel is deployed.

## Preserve the workload

Use `datalab-to/chandra-ocr-2` revision `af93b47dba1b47b6640c86ccf487ed2260ab9a09`, the exact processor/tokenizer/prompt, original page pixels, a 16,384-token context and the normal 12,384-token output allowance. The retained throughput requests use 1,624 × 2,100 decoded pixels and 3,617 prompt tokens; older frozen renders use 1,632 × 2,112 and 3,959. These are distinct inputs. Record precision changes explicitly: the maintained candidate uses block-INT8 Q8_0 text, not FP8 or unchanged-BF16 inference. Do not credit shorter output, smaller images or another checkpoint as an unchanged-workload speedup. Preserve complete table associations, equations, layout, metadata, raw responses and natural EOS alongside numerical outputs and carried state.

Model weights stay outside Git. The downloader checks pinned file sizes and hashes, refuses existing mismatches and keeps partial files out of accepted names. The inventory verifier checks tensor shapes/ranges and the embedding/output-head bytes. The native importer performs its own authenticated, bounded import; it is not authorized by a model name alone. The pinned model and upstream source are recorded under [provenance](provenance).

## Endpoint compatibility

The service uses model alias `chandra`, `/v1/models` and `/v1/chat/completions`; health and model listings do not load inference or extend its idle lifetime. The router accepts `X-Chandra-Backend: northstone`, `waystone` or `auto`, and backend-specific base URLs. A submitted request is never replayed automatically, and capacity remains held until generation has actually completed or cancellation has retired the worker.

The ordinary endpoint is locally validated and available at the recorded boundary. The router listens on loopback and its private LAN address, and a local GET to the LAN model route passed, but an independent LAN peer timed out after ten seconds; kernel logs explicitly show UFW blocking TCP port 8002. No matching allow rule or firewall change was present at that observation. The targeted wired-LAN remedy requires owner authentication. Remote LAN access remains blocked and remote OCR is untested; local gateway availability does not establish remote-client reachability. This later network finding does not change the accepted throughput or idle cutoffs.

The following CLI form completed native and scanned two-page PDFs through the installed SYCL Waystone route, as well as the prior Vulkan route:

```sh
MAX_VLLM_RETRIES=0 VLLM_API_BASE=http://127.0.0.1:8002/backends/waystone/v1 VLLM_MODEL_NAME=chandra uv run --no-sync chandra input.pdf output --method vllm --batch-size 4 --no-html
```

The [normal C5 compatibility record](benchmarks/evidence/sycl-q8-c5-normal-service-2026-10-17.json) retains native/scanned invocations taking 36.108/35.751 seconds, with two single-submission pages each, natural stops and passing source/table/metadata and response-to-saved-output checks. The isolated validation environment also disabled OpenAI SDK retries and retained a bounded journal; `MAX_VLLM_RETRIES=0` alone disables only Chandra's application retries. These distinct PDF fixtures establish finite CLI compatibility, not five-way CLI overlap, general OCR acceptance or a sustained rate. The prior [C6](benchmarks/evidence/sycl-q8-normal-service-2026-10-16.json) and [BF16](benchmarks/evidence/sycl-cli-compatibility-2026-10-16.json) CLI results retain their own provenance.

The later current-Q8 comparison used the exact historical AMD native/scanned PDF pair: both final Markdown files and both complete metadata files are byte-identical to the retained NorthStone BF16 products, with all four exact request correspondences, natural stops and independent source checks passing. These are four rendered cases of two logical authored pages, with zero extracted images; raw boxes differ. The [current work record](docs/work-record.md#current-work) preserves the evidence route and limits: historical AMD provenance remains incomplete, and no figure-crop, live Zotero ingestion, general OCR or numerical acceptance follows. `qualified:false` remains; the separate **0.1054834 source-correct pages/s** measurement retains its driver-8991 scope, with the new 9150 sustained result linked above.

The separately built F32 recurrent-projection candidate passed its synthetic comparison with baseline B2: all 2,457,600 uint32 words per arm match across eight patterns and 24 real Q8 model matrices, with zero mismatches. Its build and operator Jobs, holds and claims closed, and normal Intel was restored asleep. Eight native files in this instrumented build differ from the normal runtime; the result establishes neither normal-runtime equivalence nor qualified steady timing, full-model, E2E, performance-improvement or deployment acceptance. The [work record](docs/work-record.md#current-work) retains the current evidence route and earlier failures; the normal endpoint and its accepted sustained rate are unchanged.

## Source and offline checks

The service/client test environment is separate from the inference environments. Its existing offline checks are:

```sh
uv sync --locked --group test --group benchmark
uv run --no-sync pytest
python scripts/model_inventory.py /path/to/pinned/model --output .runtime/model-inventory.json
```

These commands check the retained service and DirectCompute tooling; they do not qualify the SYCL engine. [ChandraNative/runtime/build.cmd](ChandraNative/runtime/build.cmd) defines the separate Windows C++ library and offline shader build. Engine experiments use separately owned, resource-bounded execution; build products, models and raw runs belong in ignored project-local locations.
