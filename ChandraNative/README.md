# Native DirectCompute correctness foundation

This is a new MPL-2.0 implementation inside the Const-me/Whisper derivative. It adapts Whisper's D3D11 device, typed-buffer, shader dispatch and staging-readback architecture; upstream files and their license remain intact. Reference infrastructure: [Whisper/D3D](https://github.com/Const-me/Whisper/tree/1ce7399704d8bea92429fc429819d32991fe9152/Whisper/D3D), [Whisper/ML](https://github.com/Const-me/Whisper/tree/1ce7399704d8bea92429fc429819d32991fe9152/Whisper/ML) and [GPU profiling](https://github.com/Const-me/Whisper/blob/1ce7399704d8bea92429fc429819d32991fe9152/Whisper/Utils/GpuProfiler.cpp). This small standalone runner deliberately avoids coupling the new graph to Whisper's audio and GGML APIs.

The executable selects one Intel hardware adapter by vendor ID and a required description substring (default `A770`), refuses ambiguous matches and never falls back to WARP or the default GPU. Selection records PCI bus/device/function, DXGI LUID, vendor/device/subsystem/revision and ordinal. Use `--list-adapters` to inspect the identities without creating a D3D device, then select the tested physical board with `--pci 0c:00.0`; `--luid` or `--adapter-index` can add a session-specific guard. Invalid sentinel PCI addresses are refused. It compiles HLSL shader model 5.0 with IEEE strictness, dispatches FP32 kernels, reads results through staging resources and checks D3D timestamp-disjoint status. JSON Lines on stdout contains the selected identity, numerical errors and measured GPU timings; errors go to stderr and return a nonzero exit code. Measurements are isolated primitive timings including dispatch work, not Chandra page performance.

Build from a Windows CMD prompt with `ChandraNative\build.cmd E:\build\chandra-native`. The script invokes the existing Visual Studio 2022 Community environment and produces `chandra-native.exe`, `oracle-test.exe`, `shadercheck.exe` and `fixture-check.exe` outside the source tree. Run `E:\build\chandra-native\oracle-test.exe` for the CPU oracle and `shadercheck.exe shader-directory` for CPU-only shader compilation. Then run `E:\build\chandra-native\chandra-native.exe --pci 0c:00.0 --shader-dir E:\repositories\chandra-ocr-windows\ChandraNative\shaders` for the PCI-identified GPU route. For an independently staged build substitute that stage's absolute shader directory. `--small-only` omits the production-shaped 1000-step test; `--adapter` supplies a different unique Intel description substring. Do not overlap this runner with full-model GPU work when collecting measurements.

The BF16 shader unpacks two stored 16-bit values from each R32_UINT element into FP32, checking all 65536 patterns; finite values, infinities and signed zeros must preserve their exact FP32 bits, while NaN payloads may canonicalize. This is actual BF16 unpacking, not an FP16 reinterpretation. RMSNorm tests use four rows of width 2560 with epsilon 1e-6 against a double oracle; gated RMSNorm multiplies normalized values by the effective learned weight and `silu(z)`. The passed weight is the effective scale: callers must apply the appropriate model-specific learned-parameter convention, including text RMSNorm's `1 + weight` convention if required by the pinned graph.

The recurrence follows [Transformers `torch_recurrent_gated_delta_rule`](https://github.com/huggingface/transformers/blob/469230357aab0f2b303b0d638c1f8d06edb14184/src/transformers/models/qwen3_5/modeling_qwen3_5.py): first `S = exp(g) * S`, then `delta = beta * (v - k^T S)`, then `S = S + k delta^T`, then `y = q^T S`. Q and K are supplied after L2 normalization, with Q additionally divided by sqrt(key dimension); beta is already post-sigmoid and g is already the negative log decay. Each GPU thread owns one value column, computes both reductions in increasing key order and retains state in an FP32 UAV. The CPU FP32 and double oracles evaluate the same equations independently on CPU. The scalar CPU fixture checks hand-calculated outputs 1 and 2.5. Synthetic vectors use a deterministic integer generator, avoiding random state and transcendental fixture-generation differences.

The GPU suite checks 32 tokens with 2 heads and an 8×8 state, then 1000 tokens with the pinned model's 32 value heads and 128×128 state per head. Expanded Q/K heads are supplied directly; the graph caller must repeat the 16 key heads to 32 value heads. Prefill loops sequentially through tokens in one dispatch; decode performs one dispatch per token. Outputs and final state must both match the double oracle within 2e-5 maximum absolute error, decode must match prefill within 2e-5, and clearing state followed by repeated prefill must reproduce state and output exactly. These are bounded synthetic fixture gates, not established error budgets for trained Chandra weights or document accuracy.

The [retained synthetic summary](evidence/synthetic-summary.json) records the successful logical A770 run on 2026-10-03, source hashes, tools and limitations. DXGI exposed two A770 matches; the initial default-selection attempt correctly refused ambiguity, and that historical run explicitly selected index 0. Later WDDM inspection found its PCI address unavailable (sentinel values), so the historical result does not establish physical PCI binding. All 65536 BF16 patterns passed. RMSNorm maximum absolute error versus double was 2.44e-7; gated RMSNorm was 7.00e-7 at width 2560 and 3.34e-7 at width 128. The 1000-token production-shaped recurrence had state error 2.17e-7 and output error 2.45e-8 versus double, with exact decode/prefill and reset agreement. Its sequential prefill measured 78.44 ms GPU time; 1000 decode dispatches measured 52.83 ms GPU time and 57.26 ms wall time. These are one-run observations, not benchmark distributions or full-layer performance; zero-error synthetic equivalence does not establish trained-weight accuracy.

The [trained activation summary](evidence/trained-activation-summary.json) records a subsequent recurrence check on the physically identified A770 at PCI `0c:00.0`, DXGI index 1, LUID `00000000:000102d9`, vendor `8086`, device `56a0`. A CPU FP32 full-model run exported 801 tokens from the first linear-attention layer on a tiny synthetic image, including the source-normalized/scaled Q/K, V, learned log decay and beta, chunked-reference output and final state. Native output error versus that trained chunk reference was 1.91e-6 and final-state error was 1.73e-5, using 86.4% of the unchanged 2e-5 absolute gate. Prefill/decode and reset agreed exactly for output and state. Sequential prefill measured 57.75 ms GPU time; 801 decode dispatches measured 42.42 ms GPU and 56.06 ms wall time. This is one layer's recurrence on one controlled processor profile; normalization, projections, convolution and gate transformations still ran in the CPU source graph.

See [the fixture format](fixture-format.md) for strict JSON/binary hashes, shapes, stage semantics, reproducible commands and CPU rejection tests. The importer checks fixture identity before creating a GPU device; `--fixture-sha256` binds a replay to the retained metadata. Windows BCrypt format/hash validation passed for the trained fixture, and the portable native importer passed 18 valid/malformed format cases. A Q/K upper-envelope guard was added after the recorded GPU run and checked on CPU without changing GPU arithmetic; the summary distinguishes GPU-build hashes from current source hashes. Fixtures and raw runs remain local ignored artifacts, while aggregate summaries retain the evidence boundary.

`fixture_dump.cpp` exports a portable 1000-token 2-head 8×8 CPU fixture and expected FP32 results. Compile it with the same strict floating-point flags, pass an output filename, then run `validate_transformers.py fixture-file installed-modeling-qwen3-5-source`. The Python checker requires an already installed PyTorch, extracts the actual source fallback function with AST, disables its hub-kernel decorator, and executes only CPU tensors. NorthStone's installed source agreed with the C++ fixture to 2.98e-8 final-state error and 2.24e-8 output error. Source and fixture hashes bind this check; the check does not import or execute the complete model or its optimized fused kernel.

This is a recurrent primitive, not a whole recurrent layer or full Chandra implementation. Unsupported stages include projections, depthwise causal convolution, the learned decay/beta transformation, Q/K normalization/head expansion in HLSL, recurrent output projection, full-attention and vision graphs, tokenizer/image processor, model importer, generation and HTTP serving. Value dimension is limited to 128 by this kernel's dispatch shape. The sequential prefill is a correctness reference; replacing it with a chunked parallel delta algorithm requires equivalence tests. No quantized weights or FP16 recurrent state are used.
