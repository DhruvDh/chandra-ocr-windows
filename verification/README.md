# Full-model numerical reference

`export_logits.py` runs the pinned Chandra OCR 2 graph with explicitly selected CPU FP32 or XPU BF16 weights. It uses eight CPU threads, eager attention, the repository OCR prompt, and the production NorthStone processor size profile (`shortest_edge=3136`, `longest_edge=3145728`). Pillow decodes input pixels to RGB because the existing ROCm torchvision build lacks a PNG decoder. No model execution falls back between devices or precisions.

Pass `--model`, `--image`, `--prompt`, `--response`, and a new private `--output` directory. The response may be a retained OpenAI completion JSON or plain UTF-8 text; its exact bytes are hashed, its content is retokenized without special tokens, and every teacher token is recorded. The default run captures last-prefill logits and eight cached teacher positions. `--no-cache-check` measures the final cached row against a complete uncached forward. Cached decoding explicitly uses the checkpoint's three-dimensional M-RoPE positions and retained rope delta. Generic generation preparation alone does not establish those positions.

`--full-teacher` performs one full-response forward and selects complete vocabulary rows at teacher offsets 0, 7, 31, 63, 127, 191, 255, 319 and the last token (deduplicated and bounded by response length). Metadata records the complete teacher prefix and each selected target, so candidates compare exactly the same conditional distributions. `--precision bfloat16 --device cpu` provides a sequential CPU calibration of precision error, separate from GPU backend error.

The raw `logits.f32` file contains little-endian FP32 row-major data with shape and SHA-256 recorded in `metadata.json`; all 248,320 vocabulary entries are retained. Metadata includes source/runtime versions and hashes, input tensor hashes, the model revision, prompt/image hashes, prefix and target token IDs, absolute prediction positions, and finite/shape/dtype/hash records for all full-attention, convolution and recurrent cache tensors. The default cached run writes partial logits incrementally; an admission record or partial output alone is an incomplete run. Raw artifacts belong outside Git.

`--activation-fixture` captures the first trained linear-attention prefill's expanded heads, L2-normalized queries and keys (epsilon 1e-6), query scaling by `1/sqrt(128)`, values, post-transform negative log decay and post-sigmoid beta. The `chandra.native.delta.v1` fixture records byte offsets, lengths, dimensions and hashes for each input and expected output/state in `activation.f32`. The reference result comes from Transformers' PyTorch chunk delta-rule fallback with zero initial state. A native recurrent scan can differ by ordinary FP32 accumulation error; this fixture validates an operator on trained activations, not the full native graph.

The October 3 CPU reference used PyTorch `2.13.0+rocm10.0.0`, Transformers `5.18.0` and Python 3.12. The frozen tiny page produced 801 prefill tokens and 832 vision patches. All nine full-vocabulary cached rows and 64 cache tensors at each position were finite, and all eight supplied NorthStone teacher tokens were greedy choices of the CPU FP32 reference. Cached versus uncached final logits had maximum absolute difference `7.62939453125e-6` and RMS difference `9.790667263587238e-7`; the greedy token agreed. The full response contained 394 retokenized teacher tokens. These are reference preparation results, not Intel acceptance or complete OCR correctness evidence.

The ordinary Transformers loader briefly retained checkpoint mappings alongside FP32 weights: observed peak RSS was about 29.9 GiB, while a measured steady snapshot contained 17.75 GiB anonymous memory and 0.43 GiB file-backed memory. Coordinate allocations before execution; the approved run budget was revised to 32 GiB RSS, with at least 30 GiB system memory available at admission, at least 4 GiB available during execution and at most 24 GiB private anonymous memory during execution. Do not infer admission from checkpoint byte size alone.

The sequential CPU BF16 calibration used the same full-response sparse positions. All nine greedy tokens agreed with CPU FP32; maximum logit difference was `0.9596428871`, maximum full-vocabulary KL divergence was `4.9966655627e-7`, and maximum target-token log-probability difference was about `1.63e-5`. Sampled reference top-one versus top-two margins ranged from 7.65 to 20.39, so this confident sample does not establish behavior at close decisions. BF16 resident peak was about 9.06 GiB. `compare_exports.py` verifies binary hashes and identical conditional inputs before calculating full-vocabulary metrics; it deliberately reports measurements without substituting its own acceptance policy.

`--all-teacher` retains every conditional distribution across the complete retokenized response, rather than selecting sparse rows. The tiny response has 394 tokens, producing a 391,352,320-byte payload per precision. A complete CPU FP32 versus CPU BF16 comparison retained identical greedy choices at all 394 positions, including a reference top-one margin of only `0.0035533905`. Nevertheless, maximum full-vocabulary KL divergence was `0.1619090374` and maximum teacher-token log-probability difference was `0.4402679924`; maximum raw/centered logit differences were `2.5165343285`/`2.4983003847`. Those distribution changes were hidden by the earlier confident sparse sample. One supplied NorthStone teacher token differed from both CPU greedy choices in a table bounding-box digit (teacher 6 versus CPU 7), illustrating why teacher forcing alone does not prove exact complete OCR output agreement. The response body is retokenized without an appended EOS; termination is checked separately by serving and OCR gates. `--attention eager|sdpa` records and selects the attention backend explicitly.
