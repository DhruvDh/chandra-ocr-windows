# Full-model numerical reference

[The curated numerical evidence](evidence/README.md) records the current measurements, source/input hashes and excluded SDPA route. This workflow compares the pinned Chandra OCR 2 checkpoint `af93b47dba1b47b6640c86ccf487ed2260ab9a09` with an independent CPU FP32 graph before assessing Intel execution. Use a checkpoint directory whose full payload has already passed the recorded SHA-256 inventory verification. The exporter records the supplied directory's configuration and tokenizer hashes; it does not authenticate arbitrary weights merely because the revision string is recorded.

The matched-version CPU oracle is pinned in `cpu/pyproject.toml` and `cpu/uv.lock`: official CPU-only PyTorch `2.14.1+cpu`, torchvision `0.29.1+cpu` and Transformers `5.18.0`, with explicit CPU index mappings. Run `uv sync --frozen --python 3.12` from `verification/cpu`, then invoke `verification/cpu/.venv/bin/python verification/export_logits.py` from the repository root. Required arguments are `--model`, `--image`, `--prompt`, `--response` and a new private `--output` directory. The response accepts a retained OpenAI completion JSON or plain UTF-8 text. Raw artifacts remain outside Git.

The processor uses Pillow RGB decoding and the production NorthStone size profile, `shortest_edge=3136`, `longest_edge=3145728`. The frozen tiny image yields 801 prefill tokens and 832 vision patches. The exact prompt/image bytes, processed tensor hashes, prefix tokens, teacher targets and absolute prediction positions identify each conditional distribution. The response body is retokenized without special tokens or an appended EOS; teacher-forced measurements do not establish termination.

The default export retains last-prefill logits and eight cached teacher positions. `--check-cache-equivalence` (legacy alias `--no-cache-check`) also compares the final cached row with a complete uncached forward. Incremental decoding explicitly uses one input token and the checkpoint's three-dimensional M-RoPE positions plus retained rope delta. `--all-teacher` captures all 394 response-body conditional distributions; `--full-teacher` selects nine sparse rows and is useful for initial diagnostics only. `--device cpu|xpu`, `--precision float32|bfloat16` and `--attention eager|sdpa|hybrid` explicitly select execution. Hybrid resolves to vision SDPA and text eager; the exporter asserts the resolved configuration. The Waystone wrapper records bootstrap changes and enforces SDPA backend selection independently.

`logits.f32` contains little-endian FP32 row-major data covering every one of 248,320 vocabulary entries. A complete tiny export is 391,352,320 bytes. `metadata.json` records shape, payload hash, source/runtime versions and hashes, input identity, memory observations and finite/shape/dtype/hash checks for full-attention, convolution and recurrent cache tensors. There are 64 cache tensors per retained position; recurrent state stays FP32 on Intel. `compare_exports.py` verifies exact conditional input identity, processed tensor hashes, file length and payload hash, then processes one float64 row at a time through read-only mappings. It reports raw and centered logit errors, full-vocabulary KL divergence, greedy choices, top-two margins and teacher-token log-probability differences. It supplies measurements without imposing an arbitrary acceptance tolerance.

The complete matched-version teacher-forced measurements collected October 3 are summarized below. Agreement alone hides probability changes near ambiguous decisions; maximum KL and target log-probability error remain visible alongside it.

All listed differences in greedy choices were bounding-box digits in this tiny page. Hybrid differed from CPU FP32 at teacher offsets 47, 124 and 182, with CPU top-two margins approximately 0.10514, 0.00357 and 0.08926. CPU FP32 versus CPU BF16 itself differed at two positions, demonstrating a precision boundary separate from device behavior. The earlier ROCm-wheel CPU 2.13 measurements and nine-row sparse samples are retained as exploratory results; they do not replace the complete matched-version oracle.

Cached versus full computation is a separate gate. CPU FP32's final row had maximum difference `7.62939453125e-6`, RMS `9.79066726359e-7` and the same greedy token. Intel eager had maximum `0.125`, RMS `0.0104142`; hybrid had maximum `0.0625`, RMS `0.00966185`, with finite tensors and the same greedy token. Strict Intel text SDPA failed this test with maximum `5.875`, RMS about `1.017` and divergent cached digits, despite close full teacher-forced measurements. Matched CPU BF16 SDPA had maximum `0.125`, RMS `0.01260` and the same greedy token. Full-forward SDPA agreement therefore cannot promote its cached generation path.

`--greedy-max-tokens` captures an independent complete response with an explicit output allowance and the installed Chandra helper's stop set: checkpoint EOS 248044 plus assistant-turn end 248046 (`<|im_end|>`). Partial token/text receipts and periodic CPU memory checks remain available during generation. The corrected CPU FP32 tiny run completed in 187.47 seconds with 395 generated tokens, stopping on 248046 below its recorded 512-token allowance. `compare_ocr.py` found all six ordered blocks, labels, prose, equations and table rows/cells identical to NorthStone; HTML differed only in table y0 by one normalized unit, equivalent to 0.528 pixels on this 528-high image, with box IoU `0.99565217`. The matched Intel hybrid tiny run also completed with 395 tokens and a stop reason, in 82.18 seconds. Its HTML matched CPU FP32 exactly outside bounding-box attributes: all ordered labels, prose, equations and table cell associations were identical. Maximum box-coordinate difference was two normalized units (0.816 pixels horizontally); vertical changes were at most one unit (0.528 pixels), and minimum box IoU was `0.95454545` for an equation block whose height changed from 21 to 22 normalized units. This establishes the tiny synthetic page boundary; representative pages, repeated requests and cancellation remain separate gates.

An earlier oracle run used only the checkpoint generation config's EOS 248044. It correctly finished the first page at assistant-turn token 248046 but continued into another assistant turn and reached its 512-token limit. That run remains a termination failure; its extracted first-turn analysis is explicitly a derivative, not a successful run. Another initial manual-generation experiment omitted M-RoPE preparation and replayed the prefix; its large cached/full discrepancy was an exporter error. Those failed artifacts are preserved separately from trusted references.

`--activation-fixture` exports the first trained linear-attention prefill for native operator checking. The `chandra.native.delta.v1` payload retains expanded value heads, L2-normalized queries/keys (epsilon 1e-6), queries scaled by `1/sqrt(128)`, values, negative log decay and post-sigmoid beta, together with the PyTorch chunk fallback's output and final state from zero initial state. The native recurrent scan passed this 801-token trained fixture with maximum output error about `1.91e-6` and state error `1.73e-5`; this establishes an operator measurement, not a full native graph.

`sdpa_probe.py` isolates grouped-query attention with 16 query heads, four KV heads, dimension 256, query lengths 1/801 and KV lengths 801/809. It freezes BF16-rounded PCG64 inputs, compares GQA with explicit KV repetition and an independent CPU FP32 eager softmax/matmul oracle, and retains full outputs and hashes. Intel cases disable the math backend. A deliberate `is_causal=True, q_len=1` case checks upper-left causal alignment; model decoding correctly uses false for a single cached query. The CPU math probe produced bit-identical GQA/manual-repeat outputs in all six cases. Intel GQA/manual-repeat pairs were also bit-identical, but the maskless single-query, noncausal calls had maximum error about 2.07 and RMS 0.445; equivalent explicit all-true boolean masks reduced error to maximum 0.000682 and RMS 0.000138. This localizes an affected mask/dispatch condition rather than a GQA repetition difference. An explicit-mask workaround is a later separate candidate; serving remains on the checked hybrid route. See the curated record for every case and exact evidence limits.

Coordinate memory before running an oracle. The ordinary Transformers loader briefly maps checkpoint payload alongside FP32 weights: observed peak RSS was about 29.9 GiB, with a steady snapshot around 17.75 GiB anonymous memory. The approved Linux CPU gates require at least 30 GiB system memory available at admission, at least 4 GiB during execution, at most 32 GiB RSS and at most 24 GiB anonymous memory. The exporter checks admission, post-load state and retained positions; greedy generation checks every 32 tokens. Runtime artifacts report actual memory, including file-backed mappings and swap, rather than inferring it from checkpoint size.
