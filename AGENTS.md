# Work on Chandra for Windows

This repository preserves Const-me/Whisper's history while adding Chandra OCR 2 inference, numerical validation and endpoint routing for Windows Intel GPUs. Read [Readme.md](Readme.md), [the design](docs/design.md) and [the work record](docs/work-record.md) before resuming. Keep the original MPL-2.0 license and upstream attribution; model weights have their own license.

The normal A770 endpoint now uses the fused-vision SYCL profile at C4, batch/microbatch 128, with four logical CPUs available to its owned processes and inference thread counts one. Its finite installed-profile operational checks, including source/configuration readback, cold demand, four-request overlap, fifth-request refusal, passive 300-second idle policy, cancellation and recovery, and the final active-lease-loss case, are recorded in the [normal-profile lifecycle evidence](benchmarks/evidence/sycl-normal-service-2026-10-16.json). The [native and scanned CLI checks](benchmarks/evidence/sycl-cli-compatibility-2026-10-16.json) also passed, with saved Markdown and metadata hashes identical to the earlier Vulkan outputs. Two separate [sustained original-endpoint observations](benchmarks/evidence/sycl-vision-affinity-repeat-2026-10-16.json) reached 0.0742634 and 0.0742734 correct pages/s, with all 120 source checks passing and clean closure, about 49.6% above the single Vulkan observation. C4 is best among the admitted configurations tested, not a hardware ceiling. The profile still reports `qualified:false`; broader numerical and OCR qualification remain open. See [the engine guide](docs/sycl-engine-trial.md) for those limits and the proposed Q8_0-KV comparison. Keep transient process state in local operational records and inspect it before taking over.

The October 15 backend decision authorizes maintained engines, including AdaptiveCpp, XPU or OpenVINO when evidence supports a separate candidate. Preserve the original SYCL startup failures and DirectCompute implementation as historical references; their progression holds do not govern a new engine. Bounded complete-page runs and provisional timings are allowed to learn about a candidate before promotion.

Correctness precedes performance. Pin the model revision, processor, runtime and input pixels; compare numerical outputs and complete OCR before promoting a faster implementation. A kernel probe is evidence for that kernel, not proof that the full model works. Record failures and missing measurements as such. Never silently fall back to a CPU, change precision, trim image dimensions or output allowance, or substitute a different checkpoint.

The [independent CPU FP32 reference](benchmarks/evidence/sycl-vision-cpu-reference-2026-10-16.json) resolves the specific native-0 OFF/ON divergence concern: fused vision has 0.853% final-conditioning relative L2 error, versus 12.282% for the original path. Preserve the one-page whole-vision scope, residual tails and input-normalization limitation; no general numerical equivalence or acceptance threshold is established. Keep implementation edits isolated from the checkout used by running services, including automatic restarts; read-only hash checks do not protect against concurrent source writes.

Keep installed tools, environments, models, private host configuration and raw runs under ignored project-local locations. Use synthetic or explicitly authorized public benchmark documents. Do not copy research files, live Zotero state, credentials or machine-private paths into this public repository. Preserve the owner's other services and coordinate GPU allocation before loading another model.

The HTTP boundary accepts only supported model and inference routes. Health and model listings must not start inference. Hold capacity until generation has actually stopped, including after cancellation, and never replay a submitted request automatically. Test concurrency, cancellation and failure with isolated workers before deployment.

Write ordinary prose as one physical line per paragraph. Keep source, setup, measurements and remaining work discoverable here, with concrete commands and honest evidence boundaries. Retain useful failed experiments and necessary build inputs; stop task-owned producers deliberately when they are no longer needed.

Claude delegation is disabled for this work until the owner explicitly asks to resume it. The owner temporarily selected GPT-6 Astra at ultra for this backend evaluation. Every new or revised script requires literal `codex --no-daemon review` before execution; a review through `codex exec` does not substitute for that command.

Use Luna for quiet current-account usage monitoring. Report actionable low-capacity warnings or an observation failure; do not send routine updates. Warn at five percent remaining and stop at a clean boundary when authenticated current-account capacity is exhausted or restricted. Unknown capacity is not zero, and another account's limits do not identify this task's allowance.
